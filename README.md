# 编程行为监控分析插件 0.2.1 Pilot

这是一个 JupyterLab 4 的本地前后端扩展。教师先输入题目，可选填本题希望考察的
知识点；系统给出可编辑的知识点和测试建议，教师确认后发布题目方案。学生选择
已发布方案并明确确认后开始监控；停止监控后，服务端才针对完整会话执行一次 AI
行为证据分析，生成会话级结果卡和可追加的教师复核。

安装与启动命令见 [启动说明.md](./启动说明.md)，数据边界与功能说明见
[项目说明.md](./项目说明.md)；BLUEDOT 工作台的基础镜像安装见
[平台接入说明](./docs/2026-08-04-bluedot-platform-integration.md)。

## 它解决什么问题

固定的“犹豫、重复、调试”等通用标签不一定适合每道题。本版把普通教师的入口
改为“题目驱动”：

- 只填写题目也可以开始；
- 可输入本课希望考察的知识点，一行一个；
- AI 可根据题目推荐知识点和测试草稿；
- 推荐内容不会直接发布，教师可以采用、修改、删除、排序或完全自行添加；
- 高级字段默认折叠，普通教师无需编辑 JSON、阈值或底层维度代码。

每个知识点最终绑定一个可核查的行为观察维度，仍使用“可能出现/明显出现”等
证据等级，不把结果表述为“已掌握/未掌握”。发布后形成不可变的 `pilot`
版本；每次会话绑定确切版本与内容哈希，后续修改不会悄悄改变旧会话的判断依据。

## 实际工作流程

```text
教师输入题目和可选的考察重点
→ AI 推荐知识点；教师采用、编辑或自行添加
→ 教师确认知识点
→ AI 生成测试草稿；教师编辑并确认
→ 发布不可变的题目考核方案
→ 学生选择已发布方案并确认本次采集用途
→ 点击“开始监控”
→ 在 Notebook 或 Python 文件中编辑、运行、报错和调试
→ 侧栏显示“有效观察时长（证据覆盖）”及其统计口径
→ 点击“停止监控”
→ 上传剩余记录并校验连续序号
→ 服务端只为该完整会话创建一个分析任务
→ 立即生成 operation_log.json 和 process_log.md
→ AI 分析完成后生成 analysis_log.json
→ 在左侧“本次日志”直接查看或下载三份文件
→ 已配置 AI：显示本次会话的维度结果卡、证据和教学建议
→ 未配置 AI：明确显示“数据采集完成，尚未进行 AI 分析”
→ AI 分析 ready/partial 或教师复核后自动刷新同一训练记录
```

当前第一阶段只把测试作为教师确认“题目是否覆盖这些知识点”的设计草稿，不执行
这些测试，也不根据测试自动输出知识掌握结论。

新建方案使用 Profile v2；既有 Profile v1 仍可选择、启动监控并读取历史结果，
无需迁移或重新发布。

监控默认关闭。没有选择已发布方案、没有勾选本次确认，或存在未处理的旧会话时，
都不能开始新监控。停止前不会按上传批次反复触发 AI。

## 第一次使用

1. 启动 JupyterLab，打开左侧“行为分析”。
2. 点击“创建题目考核方案”，或从命令面板运行同名命令。
3. 输入题目；如有明确教学目标，可在“希望考察的知识点”中一行填写一个。方案
   名称、题目 ID 和提交方式位于“高级设置”。题目会先自动保存为部分草稿；没有
   确认知识点和测试时仍不能发布。
4. 点击推荐按钮后检查 AI 候选；可以采用候选，也可以直接新增、修改、删除和排序
   知识点。未配置 AI 时仍可完全手工完成。
5. 确认知识点后检查测试草稿，必要时修改输入、期望结果、关联知识点或启用状态，
   再确认并发布。
6. 如需 AI 推荐或会话分析，展开“AI 服务配置”，在 Jupyter Server 所在机器配置 Base URL、
   模型和 API Key。BLUEDOT 单用户试点工作台未设置专用配置路径或日志目录时，
   页面会将配置保存到 `/workspace/code/.behavior-audit/.ark_ai_config.json`。
7. 回到“行为分析”，选择已发布方案，勾选本次用途确认，点击“开始监控”。
8. 在 Notebook 中使用原生运行按钮；在 `.py` 文件中使用“运行”菜单、命令面板
   的“运行当前 Python 文件”或文件编辑器右键菜单。
9. 观察侧栏的“有效观察时长（证据覆盖） / 最低要求”。它统计代码输入、删除、粘贴和页面活动时的动作间停顿；页面离开与运行耗时不计入，但运行事件会写入日志；
   达标后再点击“停止监控”。若尚未达标，侧栏会先说明现在停止将得到“数据
   不足”，可选择继续监控或明确仍要停止。
10. 点击“停止监控”，等待剩余记录上传和会话结束。服务端会自动创建
    `sessions/<session_id>/training_record.json`；即使未配置 AI，也保留受约束的源码
    快照和行为事件。
11. 在左侧“本次日志”中，操作日志和过程日志停止后立即可查看/下载；AI 分析日志先显示“正在分析…”，仅在真实 `ready` 后可打开。
12. 已配置 AI 时按证据跳转到对应行为事件，并在“教师复核”中确认或修正；AI
    结果只是辅助判断，教师复核是单独的追加记录，不会改写原始 AI 结果。
13. AI 分析进入 `ready`/`partial` 或教师复核成功保存后，服务端会原子刷新同一个
    `training_record.json`。
14. 只有排查或研究需要时才展开“高级数据”查看兼容原始文件。

普通入口不是“全局最新日志”，也不要求双击日志才能看到主要结果。结果始终绑定
本次会话和当时选择的方案版本。

## 本次日志与自动记录

每次会话的三份可读文件位于 `sessions/<session_id>/logs/`，并在左侧固定按以下顺序显示：

1. `operation_log.json`：输入、删除、粘贴、运行成功/失败及输出，会话 finalize 后立即生成。
2. `process_log.md`：按时间顺序整理修改、动作间停顿和运行结果，会话 finalize 后立即生成。
3. `analysis_log.json`：维度结论、数据质量、行为证据与分析来源，只在 AI 分析真实 `ready` 后生成。

文件名和“查看”会在 JupyterLab 主区打开只读页签；“下载”通过经认证的当前 Jupyter 服务地址获取完整文件。“打开日志文件夹”只保留在“高级数据”中用于本机诊断，不是远程平台的日常入口。内部的 `training_record.json` 仍保留作为受控派生记录。

AI 结论只能作为辅助教学判断，教师复核单独追加保存。真实日志、会话目录和训练记录
可能包含学生代码与教学数据，不得提交到版本库或发送到外部服务、聊天或共享位置。
当前能力仍仅面向本地单用户 Pilot。

## 数据和隐私边界

- 会采集编辑、删除、粘贴、运行成功/失败、停顿、页面可见性和切换等客观事件。
- 本地 Jupyter Server 保存会话、批次回执、分析任务、结果和复核记录。
- 只有配置外部模型并在停止后分析时，分析所需的脱敏候选片段才可能发送到该
  provider；插件不会把 API Key 作为提示内容发送。
- Provider API Key 只保存在 Jupyter Server 所在机器。支持 POSIX 权限的平台
  使用 `0600` 私有文件；不要把配置文件提交到版本库、打包、聊天或共享目录。
- BLUEDOT 上述工作区回退只适用于当前单用户试点；容器重建后是否保留取决于平台对
  `/workspace/code` 的持久化策略。普通本地环境仍使用原配置位置；正式多用户部署应使用平台密钥管理。
- 不再使用当前 provider 时，在“AI 服务配置”中点击“清除已保存 Key”并确认。
- 从保存过密钥的旧版本迁移后，应在 provider 侧轮换旧密钥，再保存新密钥。
- 本机绝对路径会在提示边界脱敏；学生输入的代码、注释和错误文本均视为不可信
  数据，不能改变系统指令。

不要将 `log/` 或任何包含真实会话/密钥的目录提交或共享。

## 建议生成性能与故障排查

知识点和测试建议属于短时作者辅助请求，内部固定使用 `2048 → 4096` 的结构化
输出预算、关闭深度思考，并要求 JSON 对象。只有第一次响应因长度截断时才使用
4096 再恢复一次。会话停止后的完整行为分析继续使用 `8192 → 16384` 预算，
单次 Provider 调用最多 60 秒；默认 180 秒总预算内最多调用三次。Provider 超时
后立即重试，网络错误、429 和 5xx 在重试前短暂等待；不需要更换当前模型。

建议生成失败时，页面保留当前草稿并允许手工继续。按页面稳定错误码排查：

| 错误码                         | 建议操作                                         |
| ------------------------------ | ------------------------------------------------ |
| `ai_provider_timeout`          | 请求超过 60 秒；重试一次，仍失败时检查模型延迟。 |
| `ai_provider_network_error`    | 检查网络、DNS、TLS、代理和出口策略。             |
| `ai_provider_auth_failed`      | 检查 API Key、模型权限和 Secret 注入。           |
| `ai_provider_rate_limited`     | 稍后重试，并检查额度、QPS 和并发限制。           |
| `ai_provider_request_rejected` | 检查 Base URL、模型名和 Provider 参数兼容性。    |
| `ai_provider_unavailable`      | Provider 返回 5xx；稍后重试并查看其服务状态。    |
| `ai_response_truncated`        | 减少知识点数量或描述长度后重试。                 |
| `ai_response_invalid`          | 检查模型是否支持结构化 JSON 对象输出。           |

页面不会显示 Provider 原始响应；排查时也不要复制 API Key、真实题目、学生代码
或完整请求/响应正文。

## Pilot 限制

本工具输出的是“基于当前已采集证据的教学观察”，不是事实判决：

- 不用于自动评分、成绩、处分或排名；
- 不用于能力、知识掌握程度、人格或心理状态诊断；
- 当前保存并确认测试草稿，但不会自动执行测试或据此判断掌握程度；
- “运行成功”不等于答案正确，“停顿”不等于犹豫或心理状态；
- 模型自评值不代表正确概率；未校准规则不生成数值支持度；
- 当前版本是本地单用户 Pilot，不提供 JupyterHub 多租户隔离或正式研究校准。

## 包名和制品

- npm 包：`myextension`
- Python 包：`myextension`
- JupyterLab 插件 ID：`myextension:plugin`
- 当前 wheel：`dist/myextension-0.2.1-py3-none-any.whl`

Wheel 是预构建扩展，普通部署不需要 Node.js。它包含前端 prebuilt
labextension、服务端配置、API schemas、维度模板、信号字典和测试资源。

依赖。包元数据仍允许 Python 3.10 及以上；本次没有把 3.10–3.14 全部视为已验证
环境：


```bash
PATH="$PWD/.venv/bin:$PATH" .venv/bin/jlpm clean:all
```

## 常见问题

### 左侧没有“行为分析”

在安装该 wheel 的同一虚拟环境运行：

```bash
jupyter labextension list
jupyter server extension list
```

两项都应显示 `myextension` 已启用。若服务端未启用：

```bash
jupyter server extension enable myextension --sys-prefix
```

随后彻底停止并重新启动 JupyterLab。

### 点击停止后暂时没有结果

先观察“待上传数”和任务状态。上传、finalize、排队及模型调用都需要时间；可使用
“刷新状态”。若出现“重试上传/结束”，先重试该动作，不要删除本地数据。若显示
“数据采集完成，尚未进行 AI 分析”，说明采集已成功，但尚没有 AI 行为结论；配置
AI 服务后重试分析即可，原始记录仍保留。

### 为什么事件很多仍显示“数据不足”

事件数量不等于“有效观察时长（证据覆盖）”。它统计代码输入、删除、粘贴以及页面活动时的动作间停顿。页面隐藏、切换应用或失焦和代码运行耗时不计入；运行事件仍会写入日志。达到门槛只表示行为证据覆盖足够，与日志生成或 AI 分析等待无关。
保持 JupyterLab 页面在前台，继续编辑、运行或停留观察，直到出现“已达到最低
要求”再停止。教师仍可选择“仍要停止”，但该会话可能只能得到数据不足结果。

### Python 文件如何运行

先在文件编辑器打开 `.py` 文件，然后从 JupyterLab 顶部“运行”菜单或命令面板
选择“运行当前 Python 文件”；也可在文件编辑器中右键选择同一命令。运行前会
自动保存当前文件，结果对话框使用中文显示退出代码、耗时和标准/错误输出。

### 如何移除已保存的 API Key

展开“AI 服务配置”，点击“清除已保存 Key”并二次确认。该按钮只在服务器已保存
Key 时显示；清除后新的 AI 分析需要重新配置 Key。

### 已发布方案没有出现在下拉框

确认知识点和测试都已完成当前版本的确认，并已点击发布，而不是只保存草稿；回到
侧栏刷新已发布方案。题目、知识点或测试被修改后，相关确认会自动失效，需要重新
检查并确认。

### AI 没有推荐到我想要的知识点

AI 返回的是候选，不是发布结果。可在知识点步骤中直接新增或编辑教师知识点，也可
删除不合适的候选。未配置 AI 或推荐失败时，手工知识点仍会保留并可继续完成方案。

### 如何查看原始文件

展开“高级数据”，点击普通文件按钮打开兼容的 Markdown、时间线、原始事件或旧
分析文件。它们用于核查和排障，不是日常主流程。

## 卸载

```bash
jupyter server extension disable myextension --sys-prefix
python -m pip uninstall myextension
```

卸载软件不会自动删除既有教学数据。需要删除会话时，应先在侧栏使用精确会话确认
的“删除本次会话”；操作前按本单位数据政策处理备份与留存。
