# 编程行为分析插件：教师现场演示逐界面讲解稿

适用版本：`myextension 0.2.1`

适用场景：教师现场演示 5–8 分钟

使用方式：左列是演示人员的操作，右列内容可以直接作为现场讲解词。

## 一、打开插件

| 演示操作                             | 现场讲解词                                                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 在 JupyterLab 左侧点击“行为分析”图标 | “这里是行为分析插件的主入口。点击后，左侧会显示题目方案、监控状态、分析结果和本次日志。学生仍然在中间区域正常编写和运行代码。” |
| 指向“题目与分析方案”                 | “这个下拉框用于选择本次编程任务对应的考核方案。每个方案都绑定了具体题目、知识点和观察要求，监控开始后不能再切换。”             |
| 指向页面中的 Pilot 提示              | “页面提示说明当前结果只用于辅助教学观察，不直接用于成绩、处分或能力判断。”                                                     |
| 首次进入时点击“创建题目考核方案”     | “当前还没有已发布方案，所以先点击这里，为本次题目建立一套可使用的观察方案。”                                                   |

如果首次使用说明页出现在中间区域，可补充：

> “首次使用页说明了工具能回答什么、会采集什么，以及外部 AI 的数据边界。点击‘创建题目考核方案’后进入三步创建流程。”

## 二、第一步：输入题目

进入“创建题目考核方案”后，顶部的三个步骤分别是“输入题目”“确认知识点”和“确认测试并发布”。右上角“试点”表示当前发布的是试点方案。

| 演示操作                                   | 现场讲解词                                                                                                             |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 在“完整题目”中输入题目                     | “这里填写发给学生的完整题目。后面的 AI 建议会以这段题目为依据。”                                                       |
| 在“我想考察的知识点”中输入内容，或故意留空 | “这里可以提前填写教师明确想考察的知识点，每行一个；也可以留空，让 AI 根据题目先生成候选建议。”                         |
| 点击“高级设置”                             | “高级设置用于查看或修改方案名称、题目标识、答题形式和函数名。普通演示中通常不需要修改，系统会根据题目自动生成默认值。” |
| 指向“方案名称”                             | “方案名称用于教师在左侧列表中识别这套方案。”                                                                           |
| 指向“题目标识”                             | “题目标识是系统内部区分题目的唯一标识，适合与课程或题库中的题目编号保持一致。”                                         |
| 切换“答题形式”                             | “这里选择学生是实现一个函数，还是使用标准输入输出。选择函数形式时，还需要确认函数名。”                                 |
| 指向“函数名”                               | “函数名用于描述学生需要实现的函数入口，例如 `analyze_scores`。”                                                        |
| 点击“下一步：确认知识点”                   | “点击下一步后，系统会保存当前草稿并进入知识点确认。如果没有预填知识点，会自动请求 AI 建议。”                           |

## 三、第二步：确认知识点

| 演示操作                                           | 现场讲解词                                                                                                                                                      |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 等待“正在根据题目生成知识点建议”                   | “系统正在根据题目生成候选知识点。这里生成的是建议，不会自动成为最终方案。”                                                                                      |
| 指向“AI 建议”区域                                  | “这一部分是 AI 返回的候选项。教师可以逐条判断是否符合本节课的实际教学目标。”                                                                                    |
| 点击某个建议的“采用”                               | “点击‘采用’，这条建议会进入下方的‘最终知识点’，并自动补齐对应的过程观察内容。”                                                                                  |
| 点击某个建议的“忽略”                               | “点击‘忽略’只会移除这条候选建议，不影响已经采用的知识点。”                                                                                                      |
| 修改“知识点名称”或“知识点说明”                     | “采用后仍然可以直接修改。最终发布的是教师确认后的内容，不是 AI 的原始回答。”                                                                                    |
| 点击某个知识点的“高级观察设置”                     | “这里是这个知识点对应的过程观察规则，包括要观察的问题、哪些表现可以作为支持证据，以及哪些情况应当排除。AI 建议被采用时会自动补齐这些内容，教师也可以继续修改。” |
| 点击“上移”或“下移”                                 | “这两个按钮用于调整知识点顺序，最终结果会按这里的顺序展示。”                                                                                                    |
| 点击“删除”                                         | “删除会将不需要的知识点从最终方案中移除。”                                                                                                                      |
| 在“添加自定义知识点”中填写并点击“添加自定义知识点” | “如果 AI 没有覆盖教师需要的内容，可以在这里手工添加，整个流程不依赖 AI 才能继续。”                                                                              |
| 点击“重新获取 AI 建议”                             | “需要更多候选内容时可以重新获取。已经采用或由教师编辑的知识点会保留。”                                                                                          |
| 点击“返回修改题目”                                 | “这个按钮回到第一步。题目内容发生变化后，需要重新核对知识点和后续测试。”                                                                                        |
| 点击“我已确认以上知识点”                           | “点击确认表示教师认可当前最终知识点。系统会检查每个知识点是否具备必要的观察依据，通过后进入测试确认。”                                                          |

如果出现红色“请补全……”提示，可这样说明：

> “系统要求最终知识点具备完整的名称和观察依据。补全提示字段后再次确认即可；AI 建议只是草稿，仍需满足发布要求。”

## 四、第三步：确认测试并发布

| 演示操作                               | 现场讲解词                                                                                                         |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 等待“正在生成可编辑的测试建议”         | “系统正在根据题目和刚才确认的知识点生成测试草稿。这些测试用于帮助教师检查题目是否覆盖知识点。”                     |
| 指向“测试名称、输入、预期输出”         | “每个测试都包含名称、输入和预期输出。教师可以直接修改，最后保存的是教师核对后的版本。”                             |
| 点击测试卡片的“高级设置”               | “这里可以指定该测试对应哪些知识点，以及是否启用这条测试。每个知识点至少需要被一条启用的测试覆盖。”                 |
| 勾选或取消“启用此测试”                 | “取消后这条测试仍保留在草稿中，但不会作为当前方案的有效测试。”                                                     |
| 点击“上移”“下移”或“删除”               | “这些按钮分别用于调整测试顺序或移除不需要的测试。”                                                                 |
| 点击“重新生成测试建议”                 | “需要重新生成时点击这里。教师已经编辑的测试会保留，不会被简单覆盖。”                                               |
| 点击“添加手工测试”                     | “如果不使用 AI，或者需要补充特殊边界条件，可以手工增加一条测试。”                                                  |
| 勾选“我已核对这些测试，确认后才可发布” | “这一步代表教师已经核对输入、预期输出和知识点覆盖关系。没有确认时，发布按钮不会启用。”                             |
| 指向页面的试点说明                     | “当前版本只保存测试方案，不会自动执行这些测试，也不会根据测试直接判断学生是否掌握知识点。”                         |
| 点击“返回修改知识点”                   | “需要调整知识点时可以返回。知识点一旦修改，测试需要重新检查并确认。”                                               |
| 点击“发布试点方案”                     | “点击后会发布一个不可变的试点版本。发布成功后，这个版本会出现在左侧方案列表中，后续学生会话会绑定到这个确切版本。” |

发布成功时可说：

> “页面显示‘试点方案已发布’，说明这套题目、知识点和测试已经可以用于一次正式的演示会话。”

## 五、选择方案并开始监控

| 演示操作                         | 现场讲解词                                                                                                                         |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 回到左侧“行为分析”               | “发布完成后回到插件侧栏，刚刚的方案已经出现在‘题目与分析方案’列表中。”                                                             |
| 从下拉框选择刚发布的方案         | “选择后，本次监控和分析都会以这套方案为依据。列表中的版本号以及‘几点/几测’分别表示知识点和测试数量。”                              |
| 勾选“我已了解本次采集和试点用途” | “每次开始前都需要重新确认。本次会采集编辑、运行、报错和页面活动等客观过程事件，未勾选时不能开始监控。”                             |
| 点击“开始监控”                   | “从点击这一刻开始，插件才会采集本次会话的编程过程。监控默认是关闭的，不会在后台自动开始。”                                         |
| 指向“监控状态：进行中”           | “这里表示当前正在记录。方案选择框会暂时锁定，避免同一次会话中途更换判断依据。”                                                     |
| 指向“已采集事件数”和“待上传数”   | “已采集事件数表示本次记录到的过程事件；待上传数表示仍在本地队列、等待发送到服务端的事件。”                                         |
| 指向“有效观察时长（证据覆盖）”   | “这个进度只统计代码输入、删除、粘贴以及页面活动时的动作间停顿。运行耗时和离开页面的时间不计入，但运行成功或失败本身仍会写入日志。” |

## 六、演示学生编程过程

| 演示操作                               | 现场讲解词                                                                                               |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 打开 Notebook 或 Python 文件并输入代码 | “学生仍然使用 JupyterLab 原有的编辑方式。插件记录的是输入、删除、粘贴等客观过程，不改变学生的编程界面。” |
| 运行一段会报错的代码                   | “这次运行失败会被记录，包括运行发生的时间和错误类型，便于后续还原调试过程。”                             |
| 修改代码并重新运行成功                 | “修改和再次运行也会按顺序记录。运行成功只表示代码完成了一次执行，并不等同于答案一定正确。”               |
| 回到左侧查看进度                       | “侧栏会实时更新事件数量和有效观察时长。达到最低要求只表示证据覆盖足够，不代表分析已经完成。”             |

## 七、停止监控并等待分析

| 演示操作                            | 现场讲解词                                                                                         |
| ----------------------------------- | -------------------------------------------------------------------------------------------------- |
| 点击“停止监控”                      | “点击停止后，插件会先上传剩余事件并结束本次会话，然后才创建整段行为分析任务。”                     |
| 若出现覆盖不足提示，点击“继续监控”  | “当前证据不足时，系统会提醒现在停止可能只能得到‘数据不足’。点击‘继续监控’可以返回继续操作。”       |
| 若演示需要立即结束，点击“仍要停止”  | “点击‘仍要停止’会结束会话，但结果可能显示数据不足。这个按钮用于教师明确知道风险后仍要结束的情况。” |
| 若停止上传失败，点击“重试上传/结束” | “这个按钮会继续上传剩余记录并完成会话，不需要重新开始监控。”                                       |
| 指向“分析任务”状态                  | “停止后会依次显示排队、分析中和完成等状态。AI 响应较慢时系统会在约 180 秒总预算内自动重试。”       |
| 点击“刷新状态”                      | “这个按钮用于立即读取最新分析状态。正常情况下页面也会自动更新。”                                   |
| 分析失败时点击“重试分析”            | “如果外部模型超时或服务暂时不可用，可以点击这里重新分析；原始行为记录和已经生成的日志不会丢失。”   |

## 八、查看分析结果

| 演示操作                       | 现场讲解词                                                                                               |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 指向“本次会话结果”摘要         | “这里汇总已经完成、等待复核、数据不足以及失败的维度数量，并显示本次绑定的方案版本。”                     |
| 指向某个知识点结果卡           | “每张卡对应一个教师确认过的知识点。页面给出基于当前记录的观察结论和说明。”                               |
| 点击“查看 N 条证据”            | “展开后可以看到该结论引用的具体行为时间、事件类型和证据说明，教师可以回到客观过程核查结果。”             |
| 指向“下一步教学建议”           | “这一项根据当前观察结果提供后续教学建议，供教师参考，不会自动执行。”                                     |
| 点击“教师复核”                 | “AI 结果不是最终判定。教师可以确认当前结论，也可以修正为未发现明显证据、可能出现、明显出现或仍不确定。”  |
| 填写“复核说明”并点击“提交复核” | “复核说明是必填项。提交后会保存教师的独立复核记录，不会覆盖原始 AI 结果。”                               |
| 点击“分析详情”                 | “这里显示方案版本、结果状态、模型和分析流程等技术来源信息，主要用于核查和排障，普通教学查看不需要展开。” |

## 十一、高级数据与异常恢复按钮

这一部分不建议在正常 5–8 分钟演示中实际操作，只需在被问到时说明用途。

| 界面或按钮                                       | 作用说明                                                                                         |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| “高级数据”                                       | “用于本地诊断和兼容旧数据，不是教师日常查看结果的主入口。”                                       |
| “打开日志文件夹”                                 | “在 JupyterLab 运行于本机时打开底层日志目录，用于故障排查。”                                     |
| “刷新旧数据”                                     | “读取旧版兼容日志或历史分析文件。”                                                               |
| “输入完整会话 ID 以删除本次会话”＋“删除本次会话” | “这是受保护的删除操作。只有输入完全一致的会话 ID 才能删除本次会话及其相关工件，演示时不要点击。” |
| “放弃未完成会话”                                 | “浏览器意外关闭或上一次会话没有正常结束时，用于明确放弃该未完成会话。放弃的会话不会自动分析。”   |
| “请先放弃未完成会话”                             | “表示系统检测到未完成会话。需要先处理旧会话，避免新旧数据混在一起。”                             |

## 十二、演示结束语

> “以上就是插件的完整使用流程：教师输入题目，确认知识点和测试，发布方案；学生明确开始后进行正常编程；结束后，教师可以查看过程日志、行为证据、AI 建议并进行人工复核。页面上的每一步确认都用于保证题目方案、采集过程和最终结果之间能够对应起来。”

## 十三、现场演示推荐点击顺序

```text
行为分析
→ 创建题目考核方案
→ 输入完整题目
→ 下一步：确认知识点
→ 采用 AI 建议
→ 我已确认以上知识点
→ 核对测试并勾选确认
→ 发布试点方案
→ 回到行为分析并选择方案
→ 勾选本次采集用途
→ 开始监控
→ 输入代码、运行失败、修改、运行成功
→ 停止监控
→ 刷新状态
→ 查看行为证据
→ 教师复核
→ 查看本次日志
```
