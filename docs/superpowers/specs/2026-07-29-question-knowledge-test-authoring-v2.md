# 题目—知识点—测试确认方案 v2

日期：2026-07-29  
状态：第一纵向切片实现与本地验收完成，待安装/部署  
适用项目：JupyterLab 编程行为监控分析插件

## 1. 本轮目标

把教师的主要入口从“手工配置多个行为维度”改为三步教学流程：

1. 输入一道 Python 编程题及答题形式；
2. 确认本题考察的知识点；
3. 确认用于后续验证的结构化测试并发布试点方案。

教师可以完全手工完成。AI 只提供知识点和测试候选，不得自动写入正式方案，
不得覆盖教师输入。第一纵向切片只保存经教师确认的测试草稿，无论是否完成确认都
不执行测试，也不形成知识掌握结论。

## 2. 用户与易用性

主要用户是没有研究方法或提示词工程经验的普通任课教师。

- 题目是唯一的内容起点。
- 知识点可以直接输入；未输入时才默认请求 AI 推荐。
- AI 不可用时保留添加、编辑、删除和排序的手工路径。
- 行为证据、排除情况、信号和阈值放在“高级设置”，默认折叠。
- 普通流程不得要求教师理解 JSON、模型参数、事件编码或 possible/clear 等内部等级。

## 3. 三步流程

### 3.1 输入题目

必填：

- 方案名称；
- 题目标识；
- 完整题干；
- 答题形式：函数调用或标准输入输出；
- 函数调用形式下的函数名。

可选：

- 教师预先想到的知识点，每行一个；
- 高级设置中的语言和行为观察说明。

题干为空、函数形式缺少函数名时不能继续。

### 3.2 确认知识点

- 若教师已输入知识点，直接生成教师知识点列表，不自动调用 AI。
- 若教师没有输入知识点，调用默认提示词生成 3–6 个候选。
- AI 候选明确标记“AI 建议”。
- 教师可以接受、忽略、改名、改说明、添加、删除和上下移动。
- 进入下一步前至少保留一个知识点，并明确确认最终列表。
- 添加、编辑或调整知识点顺序时，保留已有测试草稿，但立即清空知识点确认哈希和
  测试确认哈希；教师需要重新确认知识点，并检查测试是否仍然适用。
- 删除知识点时，从测试的引用列表中移除该知识点；只有不再引用任何知识点的孤儿
  测试才被删除。仍引用其他知识点的测试继续保留，并同样清空两级确认。

### 3.3 确认测试并发布

- AI 根据题干、答题形式和已确认知识点生成结构化输入/预期输出候选。
- 每个测试必须引用至少一个当前知识点。
- 教师可以编辑名称、输入、预期输出，启用/禁用、添加、删除和排序。
- AI 失败时允许手工添加。
- 教师必须勾选“我已核对这些测试”，当前测试哈希才成为确认哈希。
- 修改测试后仅测试确认失效。
- 发布要求知识点确认哈希和测试确认哈希都与当前内容一致。

## 4. Profile v2 契约

v1 方案保持冻结和只读兼容。v2 使用独立 Schema，不给 v1 偷加可选字段。

```ts
interface IAssessmentProfileDraftV2 {
  schema_version: 2;
  problem_id: string;
  title: string;
  problem_context: {
    statement: string;
    language: 'python';
    submission_contract:
      | { kind: 'function'; entrypoint: string }
      | { kind: 'stdin_stdout' };
  };
  knowledge_points: Array<{
    id: string;
    name: string;
    description: string;
    source: 'teacher' | 'ai_suggestion';
    order: number;
  }>;
  assessment_tests: Array<{
    id: string;
    name: string;
    knowledge_point_ids: string[];
    kind: 'function_call' | 'stdin_stdout';
    input: string;
    expected: string;
    enabled: boolean;
    source: 'teacher' | 'ai_suggestion';
    order: number;
  }>;
  confirmations: {
    knowledge_points_hash: string | null;
    tests_hash: string | null;
  };
  dimensions: IDimensionDefinition[];
}
```

约束：

- v2 草稿允许在第一步只保存题目，此时知识点、测试和维度可以为空；发布版本仍
  必须至少包含一个知识点、一个对应维度，并满足启用测试覆盖。
- 知识点 ID、测试 ID 和维度 code 在一次草稿中唯一。
- 顺序必须从 0 连续递增。
- 测试引用必须属于当前知识点。
- 测试 kind 必须与答题形式一致。
- 每个知识点至少有一个启用测试才能发布。
- 知识点确认哈希覆盖题干、答题形式和知识点列表；测试确认哈希覆盖同一题目上下文、
  当前知识点确认哈希和测试列表。修改题干或答题形式也会使后续确认失效。
- 测试输入和预期输出按教师原文保存并参与哈希，首尾空白和换行不得被静默裁剪。
- 异步计算确认哈希期间若教师继续编辑，旧确认结果必须丢弃并要求重新确认，不得
  覆盖新输入。
- 添加、编辑或排序知识点不会自动丢弃测试草稿；任何知识点内容变化都会清空两级
  确认。删除知识点时只清理其测试引用，并删除引用列表变空的孤儿测试。
- v2 中每个知识点对应一个行为观察维度；该维度只解释过程证据，不单独产生
  “已掌握”结论。
- 题干、答题形式、知识点、测试、确认哈希和行为维度共同进入不可变内容哈希。

## 5. AI 辅助接口

无状态接口：

```text
POST /myextension/assessment-assist/knowledge-points
POST /myextension/assessment-assist/tests
```

知识点请求只包含：

- 题干；
- 答题形式；
- 教师可选的关注点。

测试请求只包含：

- 题干；
- 答题形式；
- 已确认知识点的 ID、名称和说明。

不得包含学生事件、Notebook 路径、身份、API Key 或历史日志。模型输出经过数量、
长度、唯一性、引用和闭合字段校验；失败返回稳定错误码，不回显原始模型内容。

## 6. 结论边界

第一纵向切片只完成“方案配置闭环”，不执行测试，也不新增正式知识结论。

- 界面明确显示“本阶段只保存测试方案，不会执行测试，也不会据此显示‘已掌握’
  或‘未掌握’”。
- 现有结果页继续显示行为观察结果。
- 不出现“已掌握”“未掌握”。
- 测试通过也不能单独证明掌握。

后续第二纵向切片只有同时具备以下证据才允许输出
“本次任务中形成较充分的掌握证据”：

1. 教师确认且与会话绑定的测试实际结果；
2. 当前会话的代码或运行输出证据；
3. 当前会话的编辑、失败、修改和验证等行为证据。

缺失任一来源时为“证据不足”或“待教师复核”；三类证据冲突时为
“证据存在冲突”。

## 7. 隐私与安全

- 推荐接口不读取或上传真实会话数据。
- 测试候选在第一纵向切片中只保存、不执行。
- 题干视为不可信数据，不能改变系统提示词。
- 错误响应和普通日志不得包含题干、AI 原始回复、密钥、身份、绝对路径或学生代码。
- 后续测试执行必须使用独立临时目录和子进程，并设置超时、输出限制、路径约束和
  环境变量清理；本地子进程不得宣传为容器级强沙箱。

## 8. 兼容与非目标

必须保留：

- v1 已发布方案、旧会话和现有行为分析可读；
- 监控默认关闭；
- 会话绑定不可变方案快照；
- 停止后只创建一次完整会话分析；
- “数据已采集”和“AI 已分析”继续分开；
- Python 版本范围不收紧。

本轮不做：

- Figma；
- 隔离测试运行器；
- AnalysisResult v2 和正式知识结论；
- 自动评分、排名、处分或长期能力诊断；
- JupyterHub 多租户或容器级强隔离；
- 历史数据迁移；
- 生产部署。

## 9. 第一纵向切片验收

- 手工路径可完成题目、知识点、测试确认和发布。
- 未填知识点时可请求 AI 推荐；AI 未配置或失败时可继续手工完成。
- 教师输入不会被 AI 覆盖。
- 添加、编辑或排序知识点时保留测试草稿并清空两级确认；删除知识点时只移除相关
  引用和因此成为孤儿的测试，并清空两级确认。
- 修改测试时保留知识点确认，只清空测试确认。
- 未完成两次确认不能发布 v2。
- 只填写题目时可以自动保存部分草稿，但该草稿不能发布。
- 确认计算期间继续编辑不会丢失输入，旧确认结果不会生效。
- 测试输入和预期输出的首尾空白在草稿、确认哈希和发布版本中保持一致。
- 本切片没有测试执行入口、测试运行结果或知识掌握结论；界面只保存结构化测试
  方案并展示明确边界说明。
- 发布 v2 的内容哈希覆盖完整题目配置；v1 回归测试继续通过。
- 高级设置默认折叠，所有表单有真实 label、错误定位和键盘操作。
- 左侧活动栏使用真实 JupyterLab 图标，窄侧栏不再显示竖排标题或横向裁切。
- 前后端全量测试、lint 和构建通过。
