# 本地会话日志查看与训练记录设计

## 目标

让普通老师从左侧“编程行为分析”面板找到每次监控会话，并在一个统一页面中查看：

- 当时采集到的原始代码快照；
- 编辑、删除、粘贴、运行、报错、停顿和页面离开等行为日志；
- AI 对各知识点的分析判断、证据和数据质量；
- 教师对 AI 结论的复核记录；
- 可供后续研究或训练处理的本地结构化记录。

本次按本地单用户 Pilot 实现。开始监控时已有的“了解本次采集和试点用途”确认
同时覆盖本地日志留存，不增加单独的训练授权开关。

## 已确认的现状

当前服务端已经保存多种本地工件，但缺少统一入口：

- 会话目录中的 `session.json`、方案和信号字典快照；
- 权威原始事件流 `raw_events.jsonl`，其中重要编辑或运行事件可包含
  `cell_source`；
- 分析 job、attempt、不可变 `result.json`、私有 prompt/response 审计快照；
- 追加式 `review_history.jsonl`；
- Markdown、时间线、AI 标签和聚合样本等兼容投影。

左栏目前只有折叠的“高级数据”，读取的是全局最新兼容分析文件。它存在三个问题：

1. 代码、事件、AI 结论和复核需要分别打开，用户无法确认它们是否来自同一会话；
2. “最新文件”不等于当前选中的会话，容易误读；
3. 原始 JSONL 不适合普通老师阅读，也没有为后续训练提供稳定的统一契约。

## 方案比较

### 方案 A：扩展现有文件按钮

继续在“高级数据”中按文件类型列出按钮。

优点是开发量小。缺点是仍然以文件为中心，无法建立
“AI 判断—证据事件—当时代码”的关联，也无法解决全局最新文件与当前会话混淆，
因此不采用。

### 方案 B：会话索引＋统一日志查看器（推荐）

保留当前权威工件，新增只读聚合层。左栏只承担会话选择和摘要，完整内容在主区域
的“会话日志”页展示。训练记录作为权威工件的规范化派生文件生成。

该方案不迁移旧数据，不复制一套新的权威状态，能复用现有 `session_id`、
`event_id`、分析结果和复核链路，因此采用。

### 方案 C：引入 SQLite 日志数据库

适合多用户、大规模检索和统计，但当前是本地单用户 Pilot。数据库会增加迁移、
备份、并发、损坏恢复和版本兼容成本，当前收益不足，因此不采用。

## 用户流程与界面

### 左栏“本地日志”

在普通流程中新增非高级的“本地日志”区，放在本次会话结果之后、“高级数据”之前。

默认显示：

- 当前会话（存在时）；
- 最近 20 个会话；
- 每个会话的题目名称、开始时间、事件数和分析状态；
- `查看日志`、`刷新`；
- 当前选中会话的 `导出训练记录` 和现有精确确认删除入口。

会话状态使用中文：

- `collecting`：采集中；
- `finalized` 且无分析 job：采集完成，尚未分析；
- `queued`：等待分析；
- `running`：分析中；
- `ready`：分析完成；
- `partial`：分析完成（部分结果）；
- `error`：分析失败。

列表不显示本机绝对路径、模型原始响应、prompt 正文或内部凭据。

### 主区域“会话日志”

点击 `查看日志` 后，通过 JupyterLab 命令打开或激活唯一的主区域日志页。
再次选择其他会话时复用该页，不不断创建标签页。

页面包含以下标签：

#### 1. 会话概览

- 题目、方案名称和版本；
- 开始/结束时间；
- 事件数量、有效观察时间和页面离开时间；
- AI 分析状态；
- 是否存在教师复核；
- 数据工件完整性提示。

#### 2. 原始代码

按 `session_seq` 和时间排列代码快照。每条显示：

- 时间；
- Notebook/Cell 或 Python 文件的相对标识；
- 事件类型；
- 运行成功、运行失败及错误摘要；
- 完整 `cell_source`。

相邻且代码内容相同的快照在展示层合并，保留关联的全部 `event_id`，
避免同一段代码重复占据页面。合并仅用于显示，不改写原始事件。

“原始代码”表示监控事件当时携带的代码快照。查看器不在事后重新读取当前
Notebook 文件，以免把监控结束后的修改错误归入历史会话。没有 `cell_source`
的事件不得伪造代码。

#### 3. AI 分析

按知识点显示：

- 当前结论和数据质量；
- AI 的理由和建议；
- `evidence_event_ids`；
- 模型、分析流程和提示词版本等必要来源信息；
- 最新教师复核结果。

点击证据编号时跳转到“行为日志”中的对应事件，并在存在代码快照时同时提供
“查看当时代码”。AI 结果继续标注为辅助观察，不显示为成绩或能力诊断。

#### 4. 行为日志

按时间显示全部权威事件，支持按事件类型筛选。每条至少显示：

- `session_seq`、`event_id`、开始和结束时间；
- 行为类型和时长；
- 文档/Cell 相对标识；
- 运行结果、错误摘要以及客观计数；
- 是否被 AI 证据引用。

错误文本和学生代码按纯文本渲染，不使用 `innerHTML`，避免代码或报错内容影响页面。

#### 5. 教师复核

显示追加式复核历史和当前生效复核。查看器不允许直接改写不可变 AI 结果；
新的复核仍调用现有 review API。

### 空状态和失败状态

- 无历史会话：显示“完成一次监控后，可在这里查看本地日志”；
- 采集完成但未配置 AI：代码和事件照常可查看，AI 页显示“尚无 AI 结论”；
- AI 分析失败：显示稳定错误码和重试入口，不隐藏原始代码或事件；
- 会话正在采集：允许查看已落盘事件，但明确标注“日志仍在更新”；
- 工件缺失或校验失败：显示“日志不完整”，不把部分内容表述为完整记录；
- 会话已被删除：关闭对应查看内容，并从列表移除。

## 数据模型

### 会话摘要

新增面向 UI 的只读摘要：

```ts
interface ILocalSessionLogSummary {
  session_id: string;
  problem_id: string;
  problem_title: string;
  profile_id: string;
  profile_version: number;
  status: string;
  analysis_status: string | null;
  started_at: string;
  ended_at: string | null;
  event_count: number;
  review_count: number;
}
```

`problem_title` 来自会话开始时固化的方案快照，不读取后来修改的草稿。

### 聚合查看模型

服务端将已有权威工件投影为：

```ts
interface ILocalSessionLogDetail {
  schema_version: 1;
  session: ILocalSessionLogSummary;
  problem_profile: Record<string, unknown>;
  code_snapshots: ICodeSnapshot[];
  behavior_events: IBehaviorEventRecord[];
  ai_analysis: IAnalysisResult | null;
  teacher_reviews: ITeacherReviewRecord[];
  integrity: {
    complete: boolean;
    missing_artifacts: string[];
    warnings: string[];
  };
}
```

查看模型中的 `ai_analysis` 只读取不可变结构化分析结果，并将最新教师复核单独返回。
不得把 AI 判断提升为教师标签，也不得用复核结果改写原始分析文件。

### 本地训练记录

每个会话可生成：

```text
<data-root>/sessions/<session_id>/training_record.json
```

结构与聚合查看模型一致，额外包含：

```json
{
  "export": {
    "schema_version": 1,
    "generated_at": "ISO-8601",
    "source_session_id": "UUID",
    "content_hash": "sha256"
  }
}
```

训练记录通过显式的“导出训练记录”生成或刷新，使用临时文件和原子替换。
它是派生数据，不是新的权威来源。分析或复核改变后，旧导出显示“需要重新生成”。

训练记录包含原始代码、客观事件、AI 分析和教师复核，但排除：

- API Key、认证 token 和其他凭据；
- prompt 正文和 provider 原始响应；
- provider 请求中的敏感头；
- Jupyter Server 数据根目录等绝对路径；
- 与教学观察无关的内部恢复或删除审计内容。

## 接口设计

新增经过 Jupyter Server 认证的接口：

```text
GET  /myextension/session-logs?limit=20&cursor=<opaque>
GET  /myextension/sessions/<session_id>/log-detail
POST /myextension/sessions/<session_id>/training-record
```

### 会话列表

- 默认按 `started_at` 降序；
- `limit` 有固定上限；
- 游标不包含可伪造的绝对路径；
- 读取每个会话目录中的固化快照和状态，不扫描兼容日志作为权威来源。

### 会话详情

- `session_id` 必须是规范 UUID；
- 路径解析必须复用会话存储的安全路径检查；
- 只返回允许公开到教师 UI 的字段；
- `evidence_event_ids` 必须与本会话事件建立交集，未知 ID 作为完整性警告返回；
- 对采集中会话给出当前一致快照，不阻塞上传。

### 训练记录

- 只允许为存在的本地会话生成；
- 由服务端从权威工件重新构建，不接受客户端上传的代码或 AI 结果；
- 写入前验证结构并计算内容哈希；
- 返回相对位置、生成时间和哈希，不返回绝对路径；
- 重复生成相同内容应得到相同内容哈希。

现有 `latest-analysis` 和“高级数据”暂时保留，作为兼容排查入口；普通日志流程不再
依赖它。

## 模块边界

### 服务端

新增独立的本地日志投影服务，职责为：

- 列出会话摘要；
- 聚合会话、事件、分析和复核；
- 生成去重代码快照；
- 校验证据引用；
- 生成规范化训练记录。

路由只负责认证、参数校验、错误映射和 JSON 返回。不得在 route handler 中复制
会话文件解析和训练记录拼装逻辑。

### 前端

- 左栏负责日志列表、刷新、选择、导出状态和打开命令；
- 主区域 `SessionLogViewer` 负责详情加载、标签切换、事件筛选和证据定位；
- API 类型和请求封装放在 service/model 层；
- 代码与事件内容使用 DOM `textContent` 或等价安全渲染。

## 文件权限、隐私与安全

- 数据默认继续保存在运行 Jupyter Server 的机器；
- 新目录使用 `0700`，新文件使用 `0600`（平台支持时）；
- 所有写入采用同目录临时文件、`fsync` 和原子替换；
- 不允许符号链接或 `..` 跳出数据根目录；
- 不从客户端接受本地文件路径；
- 错误响应不包含代码正文、绝对路径、prompt、provider 响应或凭据；
- 删除会话继续使用精确会话 ID 确认，并级联删除训练记录；
- 本项目仍是本地单用户 Pilot，不据此宣称满足多租户或正式研究的数据治理要求。

## 兼容性与迁移

- 不修改 `raw_events.jsonl`、`result.json` 或复核历史格式；
- 旧会话只要权威会话目录仍完整，就可以在新查看器中打开；
- 缺少 AI 结果的旧会话仍可查看代码和行为事件；
- 兼容投影目录不作为新会话索引来源；
- 不自动为所有历史会话批量生成训练记录，避免首次启动时大量写盘。

## 测试策略

### 服务端单元和契约测试

- 会话列表排序、分页上限和固化题目信息；
- 事件到代码快照的稳定去重；
- AI 证据 ID 与事件的关联和未知 ID 警告；
- 无 AI、分析失败、部分结果、存在复核和采集中状态；
- 训练记录字段、排除字段、内容哈希、重复生成和原子写入；
- 无效 UUID、路径越界、符号链接、缺失文件和损坏 JSON；
- 删除会话后训练记录同步消失；
- API schema 与返回模型一致。

### 前端测试

- 左栏空状态、历史列表、中文状态和刷新；
- 点击会话只打开或复用一个日志查看页；
- 代码、AI、事件和复核标签的加载与错误状态；
- 证据点击定位到正确 `event_id` 和代码快照；
- 学生代码和错误文本不能注入 HTML；
- 导出进行中、成功、失败和“需要重新生成”状态；
- 键盘操作、焦点移动、ARIA 标签和窄侧栏布局。

### 回归和冒烟测试

- 现有 Notebook 与 Python 文件监控流程；
- 停止、分析、重试、教师复核和删除；
- 前端 Jest、lint、生产构建；
- 后端 pytest；
- 构建 wheel、安装后确认 JupyterLab 前端与服务端扩展均启用；
- 完成一次真实本地会话，验证日志列表、四类数据关联和训练记录落盘。

测试和文档不得读取、复制或提交现有真实 `log/` 或数据根目录内容，使用临时目录和
合成会话。

## 验收标准

1. 完成或正在进行的本地会话可以在左栏“本地日志”中找到。
2. 选择任一会话后，代码、行为事件、AI 分析和教师复核均绑定同一 `session_id`。
3. 未配置 AI 或分析失败时，原始代码和行为日志仍可正常查看。
4. 点击 AI 证据可以定位到对应行为事件；存在代码时可以查看当时代码。
5. 原始代码来自监控事件快照，不受会话结束后 Notebook 修改影响。
6. 可以生成一个本地 `training_record.json`，其中包含代码、事件、AI 分析和复核，
   且不包含凭据、绝对路径、prompt 正文或 provider 原始响应。
7. 损坏或缺失工件会显示明确的“不完整”状态，不伪造完整结果。
8. 删除会话会同步删除其训练记录，且保留现有无内容删除审计语义。
9. 新接口经过认证并拒绝路径越界、符号链接和非法会话 ID。
10. 前后端测试、lint、生产构建、wheel 构建和安装冒烟验证通过。

## 非目标

- 不执行教师配置的测试用例；
- 不改变 AI 推理、候选事件选择或知识点判定规则；
- 不把 AI 判断作为自动成绩或最终真值；
- 不引入 SQLite、云数据库或远程训练上传；
- 不增加学生账号、教师角色或 JupyterHub 多租户权限；
- 不提供跨会话统计、班级排行榜或学生能力诊断；
- 不批量迁移或重新分析全部历史兼容日志。

## 实施顺序

1. 先为聚合服务、API schema 和安全边界补充失败测试；
2. 实现最小服务端会话列表、详情和训练记录生成；
3. 补充前端 model/service 及测试；
4. 实现左栏日志入口和主区域查看器；
5. 联通证据定位、导出和删除状态；
6. 回归验证并同步 README、项目说明、启动说明和 OpenAPI；
7. 构建并安装 wheel，执行本地合成会话冒烟测试。

每一步保持现有监控、分析和复核流程可构建、可测试；发现范围外问题只记录，不在
本轮顺手扩展。

## 回滚

本项目当前没有 Git 元数据。实现采用可独立移除的模块和兼容 API：

- 移除新增日志投影服务与三个路由；
- 移除左栏“本地日志”和主区域查看器命令；
- 删除前端新增 model/service；
- 保留现有权威会话工件、分析结果和“高级数据”入口；
- 已生成的 `training_record.json` 是派生文件，可由用户明确删除，不影响原会话。

回滚不修改或迁移现有权威数据格式。
