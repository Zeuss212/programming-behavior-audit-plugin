# 自动训练记录与跨平台日志文件夹入口设计

日期：2026-08-03  
状态：已完成口头设计确认，等待书面复核

## 背景

现有 Pilot 在 JupyterLab 左侧提供“本地日志”会话列表、日志详情查看器和手工“导出训练记录”按钮。教师的实际目标不是在插件内浏览历史日志，而是取得结构化文件，用于后续训练或研究处理。当前界面增加了查找和操作成本，也让教师难以定位服务器本机的保存目录。

本设计用一个跨平台的“打开日志文件夹”入口替代内置日志浏览流程，并把训练记录生成改为服务端自动行为。

## 目标

1. 左侧只保留一个“打开日志文件夹”按钮和简短说明，不再显示历史会话列表。
2. 会话停止后，即使没有配置 AI，也自动生成包含源码和行为事件的结构化训练记录。
3. AI 分析或教师复核更新后，自动原子刷新相应训练记录。
4. macOS 打开 Finder，Windows 打开资源管理器。
5. 继续保证训练记录不包含凭据、服务器绝对路径或未公开的模型请求内容。
6. 不删除或迁移任何已有日志、会话目录或训练记录。

## 非目标

- 不在 JupyterLab 中提供历史日志列表、日志详情页、筛选、证据导航或手工导出按钮。
- 不提供批量压缩、下载、云端同步或训练任务提交能力。
- 不尝试从远程 Jupyter Server 打开教师客户端电脑的文件管理器。
- 不改变训练记录的现有公开数据结构，也不扩展真实环境部署范围。

## 用户流程

1. 教师选择已发布方案并开始监控。
2. 教师停止监控后，服务端完成会话收尾并自动写入：
   `sessions/<session_id>/training_record.json`。
3. 外部 AI 未配置时，训练记录仍包含会话、题目方案、代码快照、行为事件、空或已有教师复核及完整性字段；刚停止的初始记录中 AI 分析可以为空，后台可按覆盖度规则写入不调用外部模型的 `ready` 结果；需要模型但未配置时，会话分析状态写入 `partial`，公开 `ai_analysis` 保持为空。
4. AI 分析进入终态或教师复核成功写入后，服务端重新生成同一文件，保持记录与当前公开状态一致。
5. 教师点击左侧“打开日志文件夹”，系统打开配置日志根目录下的 `sessions` 文件夹。

## 架构与组件边界

### 前端侧栏

`BehaviorAnalysisSidebar` 保留当前监控、分析和教师复核流程，但删除历史日志列表状态及其渲染逻辑。侧栏新增一个单一依赖 `openLogFolder(settings)`，对应一个按钮：

- 标题：`训练日志`
- 按钮：`打开日志文件夹`
- 说明：`训练记录会在每次监控结束后自动生成。`
- 请求进行中时禁用按钮，避免重复启动文件管理器。
- 成功时显示 `已打开日志文件夹。`
- 失败时显示固定、非敏感提示，不渲染服务端路径或原始异常。

删除 `SessionLogViewer`、打开日志命令、列表分页、详情读取和手工导出相关的前端模型、服务和测试。当前会话的分析结果与教师复核界面不属于历史日志查看器，继续保留。

### 固定目录打开服务

新增认证且受 XSRF 保护的 `POST /myextension/log-folder/open`。请求体只能是空 JSON 对象，客户端不能传入路径。成功响应由新增的 closed schema `log-folder-open-response-v1.json` 约束，只包含 schema 版本、请求标识、成功状态和归一化平台名称，不返回绝对路径。

服务端从既有日志根配置派生唯一目标 `<log_root>/sessions`，并执行以下保护：

1. 使用现有安全路径边界确认目标位于日志根目录内。
2. 目录不存在时以私有权限创建；不得跟随符号链接逃出日志根。
3. macOS 使用参数数组调用系统 `open`，`shell=False`，超时固定为 5 秒。
4. Windows 使用 `os.startfile(path, "open")` 打开资源管理器，不拼接 shell 命令。
5. Linux、未知平台或无桌面环境返回固定错误码和安全提示。

该功能打开的是运行 Jupyter Server 的机器上的目录。本地单用户 macOS/Windows 是正式支持范围；远程 JupyterHub 只会尝试打开服务器端目录，因此文档必须明确其限制。

### 自动训练记录服务

保留现有训练记录 schema、公开字段投影、隐私过滤、source-state hash、内容 hash、大小限制和原子私有写入。现有 `SessionLogService.export_training_record()` 从公开 HTTP 操作调整为内部自动生成能力，本轮保持其单一实现，不重命名、不复制第二套记录构建逻辑。

自动触发点：

1. 会话成功 finalize 并关联分析 job 后、分析 job 入队前生成基础记录。
2. 分析 worker 将 job 写入 `ready` 或 `partial` 终态后重新生成。
3. 教师复核成功追加后重新生成。

生成失败不得回滚或删除已完成的会话、原始事件、分析结果或教师复核。现有训练记录写入保持临时文件加原子替换；失败使用安全日志记录，并在后续状态变化时再次尝试。停止监控的核心收尾不能因派生训练记录失败而丢失原始证据。

## 删除和保留范围

删除：

- 前端本地日志列表、详情查看器、打开详情命令和手工导出 UI。
- `GET /myextension/session-logs`。
- `GET /myextension/sessions/<session_id>/log-detail`。
- `POST /myextension/sessions/<session_id>/training-record`。
- 只服务于上述公开接口的列表、详情和导出响应 schema 与测试。

保留：

- `training-record-v1.json`。
- 构建训练记录所需的内部安全详情投影。
- `SessionStore` 的训练记录读写、校验、删除级联和路径保护。
- 当前会话的 AI 状态、结果显示和教师复核流程。
- 已有日志文件和目录；实现不得清理用户数据。

## 错误处理

- 未认证或 XSRF 失败：沿用 Jupyter Server 标准响应。
- 不支持的平台或无可用桌面打开器：返回固定 `log_folder_open_unsupported`。
- 目录不安全、创建失败、打开器失败或超时：返回固定 `log_folder_open_failed`，不反射路径和异常内容。
- 前端只显示固定中文说明，并在请求结束后恢复按钮。
- 自动训练记录失败：保留全部源数据和上一个完整记录；记录安全服务端错误，等待下一触发点重试。

## 兼容性与迁移

- 本地 macOS 和 Windows 受支持，不新增第三方运行依赖。
- Windows 路径使用 `pathlib.Path` 和系统原生打开能力，不假设 POSIX 分隔符。
- Linux 和远程无桌面部署不承诺打开本地文件管理器。
- 删除三个历史日志公开接口是 Pilot 阶段的有意破坏性契约调整；README、项目说明、启动说明及 OpenAPI/schema 注册必须同步。
- 已存在的 `training_record.json` 原地保留；后续分析或复核变化会按新机制刷新。

## 测试策略

### 后端

- TDD 覆盖 macOS、Windows、不支持平台、打开器失败和超时。
- 断言打开目标只能是配置根下的 `sessions`，请求不能控制路径。
- 断言 macOS/Windows 调用不使用 shell，测试中替换系统打开器，不实际启动 GUI。
- 覆盖 finalize 后自动生成、无 AI 自动生成、分析终态刷新、教师复核刷新和失败保留源数据。
- 继续验证训练记录 schema、内容 hash、source-state hash、大小上限、`0600` 文件权限、符号链接拒绝及凭据/绝对路径排除。
- 删除的三个公开路由不再注册。

### 前端

- 侧栏只显示一个“打开日志文件夹”按钮，不出现“查看日志”“导出训练记录”或历史会话卡片。
- 覆盖请求中禁用、成功提示、失败提示、组件销毁后的迟到响应和重复点击。
- 保证当前监控、分析、教师复核和高级数据流程不回归。

### 完整验证

- 全量 Python 测试。
- 全量 Jest 测试、coverage、lint 和生产构建。
- wheel 重建、内容检查和项目 `.venv` 重装。
- Jupyter 前端/服务端扩展注册检查。
- macOS 真机 Finder 冒烟：停止合成会话后文件存在，按钮打开 `sessions`。
- Windows 分支通过隔离平台测试；最终 Windows 资源管理器真机验收需在 Windows 环境执行并单独记录。

## 验收标准

1. 停止合成监控后，无需手工操作即可出现 schema 有效的 `training_record.json`。
2. 外部 AI 未配置时，源码和行为事件存在；刚停止的初始 AI 分析可为 `null`，后台随后写入不调用外部模型的 coverage-only `ready`；需要模型但未配置时，`session.analysis_status` 为 `partial`、公开 `ai_analysis` 保持 `null`，且记录不包含凭据或绝对路径。
3. AI 或教师复核状态变化会刷新同一记录，并更新一致性 hash。
4. 左侧不存在历史日志列表、详情入口或手工导出入口。
5. macOS 点击按钮打开 Finder 的 `sessions` 目录。
6. Windows 平台适配通过单元/契约测试，且实现调用资源管理器时不使用 shell 拼接。
7. 不支持或打开失败时，界面给出安全提示，原始日志和训练记录不受影响。
8. 删除的公开路由、schema、文档和前端引用全部同步，无悬空注册或构建产物。
9. 全量后端、前端、lint、生产构建、wheel 和扩展注册验证通过。

## 回退与停止点

实现只安装到项目 `.venv`，不执行共享 JupyterHub 或远程部署。旧 wheel 保留为本地回退基线；若新功能失败，可重装旧 wheel。项目当前不是 Git 仓库，因此不能依赖分支、提交或 Git 回滚。

本阶段在完成本地 macOS 合成冒烟和 Windows 平台隔离测试后停止。Windows 真机、共享环境和正式部署需要新的阶段授权。
