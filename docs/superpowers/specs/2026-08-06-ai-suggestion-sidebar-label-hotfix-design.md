# AI 建议采用与侧栏中文方向修复设计

## 背景

`myextension 0.2.1` 当前有两个可见问题：

1. 教师采用 AI 生成的知识点建议后，点击“下一步：确认知识点”仍可能收到“请补全每个知识点的名称和观察依据”提示。名称和说明可见，但真正参与发布校验的“过程观察问题”“支持表现”“排除情况”折叠在“高级观察设置”中，错误提示没有指出具体知识点和字段。
2. JupyterLab 左侧活动栏使用 `writing-mode: vertical-rl`，并对左侧标签统一施加 `transform: rotate(180deg)`。中文标签“行为分析”因此整体倒置。

用户已确认保留“行为分析”文字，并改为从上到下、中文字符正向直立显示。

## 目标

- 有效 AI 建议保持原样，采用后可以直接确认知识点。
- AI 建议的隐藏观察字段在运行时缺失、类型异常或仅含空白时，使用确定性的安全默认内容补全。
- 仍然禁止发布缺少名称或观察依据的知识点，不放宽服务端契约。
- 如果教师手工清空必填观察字段，界面指出具体知识点和缺失字段，并自动展开对应的高级设置。
- 只修正本插件左侧标签方向，不影响 JupyterLab 其他侧栏标签。
- 重新构建并验证 `0.2.1` wheel、交付包和本地预览，使预览前端与最新交付制品一致。

## 非目标

- 不修改知识点或测试生成提示词的业务含义。
- 不修改分析算法、120 秒总预算、Provider 超时或重试策略。
- 不放宽 Profile v2、测试覆盖或发布校验。
- 不登录、推送或部署 BLUEDOT 镜像，不调用真实或付费 AI。
- 不修改 JupyterLab 全局侧栏 CSS。

## 方案比较

### 方案 A：防御性补全、精确提示和插件局部样式（采用）

在 AI 建议进入编辑状态的边界做运行时规范化。正常非空字段原样保留，缺失字段使用基于知识点名称的默认观察语句。校验层继续拒绝教师后来清空的字段，并返回具体位置。为插件侧栏标题增加专属类，仅覆盖该标签的左侧竖排变换。

优点是满足“采用后直接下一步”，同时保持正式发布数据完整；也兼容前后端短暂不一致、旧草稿或异常 Provider 响应。缺点是需要少量前端状态与样式测试。

### 方案 B：放宽发布校验（拒绝）

允许观察字段为空。实现最少，但会生成无法可靠分析的维度，破坏 Profile v2 契约。

### 方案 C：拒绝采用不完整建议（拒绝）

遇到不完整建议时显示错误并要求重新生成。保持严格，但用户仍不能直接继续，且对旧数据和混合部署不友好。

## AI 建议数据设计

### 边界规范化

`mergeKnowledgeSuggestions` 是候选建议进入教师最终知识点状态的唯一边界。该函数应对三个运行时字段分别处理：

- `evidence_question` → `evidenceQuestion`
- `support_statement` → `supportStatement`
- `exclusion_statement` → `exclusionStatement`

处理规则：

1. 值是字符串且 `trim()` 后非空：保留规范化后的原值。
2. 值缺失、不是字符串或 `trim()` 后为空：使用 `defaultEvidence(name)` 中相应字段。
3. 名称为空、ID 重复、名称重复或超过数量上限：继续使用现有拒绝规则。
4. 已存在的教师知识点和有效 AI 建议不被覆盖。

默认内容仍是可编辑的教师语言，不伪装成 Provider 原始输出。采用后的来源标记保持 `ai_suggestion`，便于界面说明其起点；教师修改任一字段后，现有逻辑将来源转为 `teacher`。

### 严格校验与错误定位

发布前仍要求每个知识点具备：

- 名称；
- 过程观察问题；
- 支持表现；
- 排除情况。

新增一个纯函数返回每个知识点缺失的字段标签。`validateAssessmentPlanState` 使用第一条错误生成明确消息，例如：

```text
知识点 2 缺少：支持表现、排除情况
```

知识点卡片使用同一结果：

- 缺少高级观察字段时自动将 `<details>` 设为展开；
- 对缺失输入设置 `aria-invalid="true"`；
- 在卡片内显示字段级提示；
- 保持键盘访问、原生 `<details>` 行为和现有焦点顺序。

这部分只改善错误定位，不替代数据规范化，也不允许空值发布。

## 侧栏标签样式设计

`BehaviorAnalysisSidebar` 的标题增加专属类：

```text
jp-BehaviorAudit-sidebarTab
```

样式只匹配左侧、竖直方向、该插件标签，覆盖 JupyterLab 默认变换：

- `writing-mode: vertical-rl`；
- `text-orientation: upright`；
- `transform: none`。

结果是“行为分析”从上到下排列，每个中文字符保持正向。标题的 `label` 和 `caption` 均保留，因此活动栏可见文字、工具提示和无障碍名称不丢失。其他插件和右侧活动栏不受影响。

## 测试策略

严格采用测试先行：

1. AI 状态单元测试先证明空白或缺失的三个观察字段当前不能直接确认；实现后应生成确定性默认值并可确认。
2. 保留有效 AI 字段的回归测试，证明正常 Provider 内容不会被默认值覆盖。
3. 校验测试覆盖具体知识点序号和字段名称。
4. 渲染测试覆盖错误卡片自动展开、`aria-invalid` 和字段提示。
5. 侧栏测试覆盖专属标题类；样式静态测试覆盖插件限定选择器、`text-orientation: upright` 和 `transform: none`。
6. 执行相关 Jest 测试、完整前端测试、完整后端测试、lint、生产构建、wheel 结构/ZIP/隔离安装验证。
7. 在隔离本地 JupyterLab 中加载新 wheel，检查前端 `remoteEntry` 与新交付 wheel 一致，并目视确认标签方向和知识点流程。

## 交付与版本

- Python/npm 版本保持 `0.2.1`，作为同版本热修复制品。
- 重新构建 wheel，产生新的 SHA-256。
- 更新 BLUEDOT 发布目录、自包含交付目录中的 wheel、`SHA256SUMS`、`MANIFEST.json` 和相关说明。
- 安装同版本时必须使用强制覆盖，并彻底重启 Jupyter Server；仅刷新浏览器不足以替换前后端资源。
- 新建本地 Git 提交和回退标签，不推送远程仓库。
- 新本地预览必须从新 wheel 的隔离环境启动，不能继续使用当前“新后端 + 旧前端”混合预览。

## 风险与回滚

- 风险：默认观察语句可能较通用。缓解方式是只在运行时字段无效时使用，并在确认页保持字段可见、可编辑。
- 风险：CSS 选择器影响其他标签。缓解方式是使用标题专属类，并同时限定 `.jp-SideBar`、左侧和竖直方向。
- 风险：同版本 wheel 容易被缓存。缓解方式是校验 wheel SHA 和 `remoteEntry`，安装时强制覆盖并重启服务。
- 回滚：Git 可回到热修复前标签 `self-contained-delivery-0.2.1`；BLUEDOT 仍按镜像 digest 回退，不删除持久化教学数据。

## 验收标准

- 采用包含完整观察字段的 AI 建议后，可以直接进入测试确认步骤。
- 采用缺失任一隐藏观察字段的合成 AI 建议后，默认内容被补齐且可以继续。
- 教师清空字段时，界面准确指出知识点和字段，自动展开错误区域，且不能发布。
- 左侧“行为分析”从上到下正向直立显示，图标、工具提示和键盘访问不变。
- 新 wheel、两个交付目录和本地预览使用同一前端构建及 wheel SHA。
- 所有适用测试、lint、生产构建和制品验证通过；真实 AI、镜像推送和 BLUEDOT 部署明确保持未执行。
