# FinColab × BAMS 课堂行为监控与简报系统设计

日期：2026-08-10

## 1. 文档定位

本文描述编程行为监控分析插件从“单个 BAMS 工作台演示”扩展到“FinColab 教师端/学生端课堂使用”的目标架构。它不替代现有插件演示设计，而是作为后续平台接入阶段的系统设计基线。

本设计严格遵守以下现实约束：

- 当前只有插件完整代码和 FinColab 前端仓库；
- 当前没有 BAMS 后端代码，也没有 FinColab 业务后端代码；
- 插件不能大幅修改 BAMS 或 FinColab 原有代码；
- FinColab 已有课程、学生、实验和工作台状态字段应继续作为原有功能的权威来源；
- 新功能优先采用旁路接口和独立页面，不修改原有接口字段语义；
- 正式跨学生同步不能只靠前端或单个 BAMS 容器完成。

## 2. 责任标签

后续任务、接口和验收项使用以下标签，避免把平台能力误写成插件能力：

| 标签 | 含义 |
| --- | --- |
| `【插件】` | 可在当前 JupyterLab 前端扩展或插件自带的 Jupyter Server 扩展内完成 |
| `【FinColab 前端小改】` | 只增加入口、独立页面、状态徽标或接口调用，不大改原有字段和页面 |
| `【共享后端必需】` | 必须由 FinColab 后端或独立同步服务提供，前端和插件无法代替 |
| `【BAMS 运维配置】` | 不要求修改 BAMS 后端代码，但需要镜像、持久卷、网络或环境配置 |
| `【BAMS 后端可选】` | 只有未来取得 BAMS 后端代码后才建议实现，不阻塞第一阶段接入 |
| `【当前不可独立完成】` | 缺少平台权限、后端或部署条件时，插件单独无法保证 |

## 3. 目标与非目标

### 3.1 目标

- 支持一节 30–40 分钟课程的持续监控；
- 网页意外关闭后，已产生的数据不丢，5 分钟内重开可续接；
- 教师端以最少信息完成课堂巡视，不展示大量技术字段；
- 教师页面关闭时，学生数据仍能自动保存；
- 下课后为每名学生自动生成一页简报并送入教师端；
- AI 不可用时仍生成基础简报；
- 对大段粘贴、缺少渐进调试等过程异常给出可复核提示，但不自动判定作弊；
- 不依赖修改 BAMS 后端代码完成第一阶段。

### 3.2 非目标

- 不在教师主界面展示每次编辑、运行和离开页面的原始计数；
- 不把完整代码和逐事件日志持续上传到 FinColab；
- 不让学生插件直接连接教师的 BAMS 容器或教师浏览器；
- 不通过浏览器本地角色字段建立安全权限；
- 不保证网页关闭后继续采集，因为 Notebook 页面关闭后不存在新的编辑行为；
- 不声称可以百分之百阻止学生使用手机或其他设备访问 AI；
- 不修改 FinColab 原有环境状态字段的名称、类型或语义；
- 不执行真实平台部署、数据库迁移或镜像推送。

## 4. 当前能力与缺口

### 4.1 FinColab 当前已有能力

FinColab 教师环境页当前已经展示：

- 实验任务名称和任务 ID；
- 所属课程、所属用户；
- 资源配置；
- BAMS 工作台状态；
- 创建时间、更新时间；
- 启动、进入、停止和释放操作。

现有状态是工作台资源状态，包括运行中、启动处理中、停止中、已停止、异常、资源未配置和待确认。教师首页已有课程数、课程用户数、实验数和运行中环境数。

这些字段继续保留，不改名、不扩展为课堂行为字段。

### 4.2 插件 0.2.2 当前已有能力

`【插件】` 当前采集端默认：

- 每累计 20 条事件或约 2 秒触发上传；
- 单批最多 100 条；
- 浏览器内存队列最多 500 条；
- 网络失败执行有限重试；
- 页面失焦或隐藏时尝试刷新队列；
- 插件服务端按序列号、批次哈希和回执进行幂等持久化；
- 完成后生成操作日志、过程日志、AI 分析日志和训练记录。

### 4.3 当前必须修复的缺口

| 缺口 | 责任 | 说明 |
| --- | --- | --- |
| 待上传队列只在浏览器内存 | `【插件】` | 改为 IndexedDB 持久队列 |
| 刷新后不能续接 collecting 会话 | `【插件】` | 根据服务器最后确认序号恢复并补传 |
| 当前失活 30 分钟只废弃、不生成简报 | `【插件】` | 改为课堂结束策略和 5 分钟断线宽限 |
| 训练记录最多 10,000 条事件 | `【插件】` | 原始日志分页/流式保存；简报不受单文档上限影响 |
| 教师无法看到跨学生状态 | `【共享后端必需】` | 单个 BAMS 容器没有班级聚合能力 |
| 教师页面关闭后仍需保存状态 | `【共享后端必需】` | 状态必须落服务端数据库，不能只存在教师浏览器 |
| 可信课程、教师和学生身份 | `【共享后端必需】` | 不能信任 URL 普通参数或 localStorage 角色 |
| BAMS 容器释放后的原始日志保留 | `【BAMS 运维配置】` | 会话目录必须挂载到持久卷 |
| 从平台创建工作台时注入环境变量 | `【BAMS 后端可选】` | 第一阶段用一次性票据替代，未来再做原生注入 |

## 5. 已选架构

采用“FinColab 管课堂，BAMS 跑工作台，插件采集，独立同步服务连接两端”的分层架构。

```text
FinColab 学生端
  │ 打开 BAMS，并在 URL fragment 携带一次性课堂票据
  ▼
BAMS Notebook + 插件
  ├─ IndexedDB：未确认的待上传事件
  ├─ 插件 Jupyter Server：完整事件、日志、简报和重试发件箱
  └─ HTTPS：心跳、摘要、最终简报
          ▼
课堂监控同步服务
  ├─ 验证一次性票据和短期令牌
  ├─ 保存课堂状态、摘要和简报
  └─ WebSocket/轮询向教师页面提供变化
          ▼
FinColab 教师端“课堂巡视”独立页面
```

同步服务逻辑上属于 FinColab 课堂业务域，但可以作为独立小服务部署，不要求修改 BAMS 后端。

## 6. 最小侵入式 FinColab 接入

### 6.1 不修改原有字段

以下对象和字段保持原状：

- 课程和成员对象；
- 实验任务对象；
- `AdminEnvironmentItem`；
- BAMS 工作台状态和启动/停止接口；
- 学生实验启动流程的既有任务创建逻辑。

课堂数据使用独立对象保存，通过既有 `spaceId + algorithmId + workbenchId` 关联，不向原有工作台响应中塞入行为分析字段。

### 6.2 教师端小改

`【FinColab 前端小改】`：

1. 教师导航增加一个“课堂巡视”入口；
2. 原环境列表可选增加一个“查看课堂状态”链接，不增加大量列；
3. 新建独立巡视页面，顶部只显示人数汇总；
4. 学生列表只显示学生、四态状态、一句话提示和一个操作按钮；
5. 点击学生后打开二级抽屉，读取详细过程和简报。

教师主页面只使用四种状态：

- `normal`：正常进行；
- `offline`：暂时离线；
- `attention`：需要关注；
- `completed`：已完成。

### 6.3 学生端小改

`【FinColab 前端小改】`：

1. 进入 BAMS 前向同步服务申请一次性课堂票据；
2. 将票据放在 Jupyter URL 的 fragment 中，例如 `#behavior-ticket=...`；
3. fragment 不随 HTTP 请求发送给 BAMS，插件前端读取后立即删除地址栏 fragment；
4. 学生记录页增加简报状态和“查看简报”入口。

现有实验任务创建、工作台轮询和 `window.open` 流程只做局部封装，不重写。

## 7. 为什么需要共享后端

以下能力不能由插件或 FinColab 前端单独安全实现：

- `【共享后端必需】` 签发并验证一次性课堂票据；
- `【共享后端必需】` 保存课堂、学生、工作台和会话的可信关系；
- `【共享后端必需】` 接收心跳和摘要，并在教师页面关闭时继续保存；
- `【共享后端必需】` 将多名学生的数据聚合成班级视图；
- `【共享后端必需】` 保存最终简报和教师批注；
- `【共享后端必需】` 按课程成员关系校验教师只能查看自己的学生；
- `【共享后端必需】` 在 WebSocket 不可用时提供轮询接口。

如果 FinColab 团队暂时不能修改业务后端，可以先部署一个独立的 `classroom-monitor-sync` 小服务。FinColab 前端和插件都只连接该服务；未来再将其合入平台后端，不要求改动插件数据协议。

纯前端方案不满足验收：页面关闭后数据会丢、身份可伪造、教师无法收到离线学生简报。

## 8. 最小数据模型

### 8.1 课堂上下文

`【共享后端必需】` 新增独立对象，不修改原课程或工作台对象：

```json
{
  "classroom_session_id": "uuid",
  "space_id": "existing-space-id",
  "algorithm_id": "existing-algorithm-id",
  "workbench_id": "existing-workbench-id",
  "student_id": "trusted-user-id",
  "starts_at": "ISO-8601",
  "ends_at": "ISO-8601",
  "ai_policy": "prohibited"
}
```

### 8.2 教师巡视摘要

后端可以保存详细计数，但教师列表只读取：

```json
{
  "classroom_session_id": "uuid",
  "student_id": "trusted-user-id",
  "status": "attention",
  "message": "离开页面后粘贴了大段代码，建议课后复核",
  "last_activity_at": "ISO-8601",
  "brief_status": "pending"
}
```

不向教师主表暴露编辑次数、粘贴比例等技术字段。

### 8.3 学生简报

```json
{
  "brief_id": "uuid",
  "classroom_session_id": "uuid",
  "student_id": "trusted-user-id",
  "status": "complete",
  "data_completeness": "partial",
  "active_duration_ms": 1800000,
  "run_summary": "运行 8 次，其中 5 次成功、3 次失败",
  "process_highlights": [
    "完成了主要函数并运行测试",
    "出现边界条件错误后进行了修改",
    "最终通过本节课配置的测试"
  ],
  "attention_message": null,
  "detail_url": "platform-controlled-url",
  "generated_at": "ISO-8601"
}
```

简报正文一页以内。完整事件和代码证据仍在 BAMS 持久目录中。

## 9. 长时监控、自动保存与恢复

### 9.1 正常采集

1. `【插件】` 捕获事件后先写入 IndexedDB；
2. `【插件】` 每约 2 秒或累计 20 条向插件 Jupyter Server 上传；
3. `【插件】` 服务端写入不可变批次日志并返回最后连续序号；
4. `【插件】` 收到回执后才从 IndexedDB 删除已确认事件；
5. `【插件】` 每 10 秒生成轻量摘要；
6. `【插件 + 共享后端必需】` 将摘要上传同步服务；
7. `【共享后端必需】` 幂等保存后供教师端读取。

只要页面保持打开并且批次持续到达，30–40 分钟不会因为原有 30 分钟清理任务而中断。实现时仍需将清理策略改为课堂上下文驱动，避免规则冲突。

### 9.2 网页关闭

1. `【插件】` 使用 `pagehide`/可见性事件尽力刷新，但不把它视为可靠保证；
2. 已进入 IndexedDB 或插件服务端的数据保留；
3. `【共享后端必需】` 60 秒未收到心跳，将教师状态改为“暂时离线”；
4. 不继续制造虚假的编程事件；
5. 进入 5 分钟恢复窗口。

### 9.3 五分钟内重开

1. `【插件】` 读取本地课堂会话 ID；
2. `【插件】` 查询插件服务端最后确认序号；
3. `【插件】` 恢复 collecting 会话，而不是要求放弃；
4. `【插件】` 从 IndexedDB 补传大于确认序号的事件；
5. `【共享后端必需】` 收到心跳后将状态恢复为“正常”；
6. 简报记录一次断线，但不自动判为异常。

### 9.4 超过五分钟或下课

- `【插件】` 插件服务端后台任务对已收到事件执行部分终结；
- `【插件】` 先生成不依赖 AI 的基础简报；
- `【插件】` AI 可用时异步补充叙述，不阻塞基础简报；
- `【插件】` 使用持久发件箱重试上传最终简报；
- `【共享后端必需】` 保存简报并将学生状态改为“已完成”；
- 如果 BAMS 容器不可达，`【共享后端必需】` 根据最后已存摘要生成平台兜底简报，并标记 `data_completeness=partial`。

## 10. 实时更新策略

- 原始行为批次只在浏览器与当前 BAMS 插件服务端之间传输；
- 课堂同步服务每 10 秒最多接收一份摘要；
- 教师端优先使用 WebSocket 接收状态变化；
- WebSocket 不可用时每 10 秒轮询；
- 数据库记录是事实来源，WebSocket 只是通知通道；
- 教师关闭页面不影响学生上传和服务端保存；
- 教师重新打开页面时从服务端恢复当前班级状态。

## 11. AI 辅助治理

### 11.1 可由插件完成

`【插件】`：

- 学生模式隐藏插件中的 AI 生成入口；
- 记录大段粘贴、离开页面、渐进编辑、运行失败和修改过程；
- 将多个信号归纳为“一句话复核提示”；
- 单次粘贴不触发“需要关注”；
- 使用“疑似外部辅助，建议复核”，不使用“作弊”结论。

### 11.2 插件不能独立完成

`【当前不可独立完成】`：

- 阻止学生在手机或另一台电脑使用 AI；
- 屏蔽 BAMS 容器的全部外网；
- 禁止平台外浏览器标签页访问公共 AI 网站；
- 证明某段代码必然由 AI 生成。

`【BAMS 运维配置】` 如需严格考核模式，可通过容器出网白名单和不安装 AI 编程扩展降低风险。这是平台/运维能力，不应写成插件已经实现。

### 11.3 实际课堂策略

默认 `ai_policy=prohibited`：学生插件不提供 AI 生成功能，教师只看到“正常”或“建议复核”。题目同时采用不同参数、阶段检查点、隐藏测试和现场解释，避免只凭最终代码评分。

## 12. 持久化和容器生命周期

### 12.1 插件侧

`【插件】` 将会话、事件日志、简报和待发送记录写入可配置目录，建议：

```text
/workspace/result/behavior-audit/
```

写入必须保持幂等、崩溃恢复和原子替换语义。

### 12.2 BAMS 侧

`【BAMS 运维配置】` 必须确认该目录位于持久卷，而不是容器临时层；必须允许插件通过 HTTPS 访问同步服务。

如果 BAMS 当前无法提供持久卷或容器出网，正式课堂交付被阻塞。这不是插件代码可以绕过的问题。

### 12.3 FinColab 侧

`【共享后端必需】` 永久保存课堂摘要和最终简报。即使 BAMS 工作台之后被停止或释放，教师仍能查看简报。详细原始证据的保留期限由平台数据政策另行确定。

## 13. 最小接口边界

建议同步服务提供以下独立接口；不修改现有 BAMS 工作台接口：

| 接口 | 调用方 | 责任 |
| --- | --- | --- |
| `POST /v1/classroom-tickets` | FinColab 学生端 | `【共享后端必需】` 签发一次性票据 |
| `POST /v1/monitor-sessions/register` | 插件 | `【共享后端必需】` 票据换短期会话令牌 |
| `PUT /v1/monitor-sessions/{id}/summary` | 插件 | `【插件 + 共享后端必需】` 幂等保存心跳和摘要 |
| `PUT /v1/monitor-sessions/{id}/brief` | 插件 | `【插件 + 共享后端必需】` 幂等提交最终简报 |
| `GET /v1/classrooms/{id}/monitoring` | 教师端 | `【共享后端必需】` 读取四态巡视列表 |
| `GET /v1/monitor-sessions/{id}/brief` | 教师/学生端 | `【共享后端必需】` 按权限读取简报 |
| `GET /v1/classrooms/{id}/events` | 教师端 | `【共享后端必需】` WebSocket/SSE 变化通知 |

短期令牌只允许写入当前学生、当前课堂和当前会话；教师读取权限按课程成员关系判断。接口不得信任前端传来的 `role=teacher`。

## 14. 实际课堂界面

### 14.1 教师端

顶部仅显示：

- 正常进行人数；
- 暂时离线人数；
- 需要关注人数；
- 已完成人数。

主表仅显示：

- 学生姓名；
- 当前四态状态；
- 一句话提示；
- 最后活动时间；
- “查看”或“提醒”操作。

技术字段只在二级详情中展示，不要求教师上课时理解粘贴比例或事件序号。

### 14.2 学生端

只显示：

- 监控中/暂时离线/已结束；
- 已自动保存和最后同步时间；
- 本节课 AI 使用规则；
- “结束并提交”；
- 简报已自动提交或等待补传。

## 15. 降级与异常处理

| 场景 | 处理 | 责任 |
| --- | --- | --- |
| FinColab 教师页面关闭 | 后端继续保存，重开恢复 | `【共享后端必需】` |
| 插件到同步服务网络中断 | 本地持久发件箱重试 | `【插件】` |
| BAMS 本地上传短暂失败 | IndexedDB 保留并按序补传 | `【插件】` |
| 网页关闭后重开 | 5 分钟内恢复原会话 | `【插件】` |
| 离线超过 5 分钟 | 生成部分简报 | `【插件 + 共享后端必需】` |
| AI 分析失败 | 立即保留基础简报，AI 后补 | `【插件】` |
| WebSocket 失败 | 教师端退化为 10 秒轮询 | `【FinColab 前端小改】` |
| BAMS 容器停止 | 平台保留最后摘要和简报 | `【共享后端必需】` |
| 容器释放且无持久卷 | 详细日志可能丢失，阻塞正式验收 | `【BAMS 运维配置】` |
| 无共享后端 | 只能做单容器演示，不能宣称班级实时同步 | `【当前不可独立完成】` |

## 16. 分阶段实施

### 阶段 0：现有插件演示

- 保持单个 BAMS 容器内采集、日志和分析；
- 不宣称教师端已收到学生数据；
- 继续使用现有 `0.2.2` 演示基线。

### 阶段 1：插件可靠性改造

只修改插件：

- IndexedDB 持久队列；
- collecting 会话恢复；
- 5 分钟宽限和课堂结束时间；
- 基础简报；
- 持久发件箱；
- 10,000 事件上限治理；
- 学生端 AI 入口隔离和过程异常提示。

阶段 1 可以独立开发和测试，但没有共享后端时只能验证本地可靠性。

### 阶段 2：独立同步服务和 FinColab 小改

- 新建课堂票据、摘要、简报和教师读取接口；
- FinColab 学生启动页追加一次性票据 fragment；
- FinColab 教师端增加独立“课堂巡视”页面；
- 不迁移或修改原有环境状态字段；
- 联调跨学生实时状态和自动简报。

### 阶段 3：可选 BAMS 原生集成

取得 BAMS 后端代码和团队授权后，再考虑：

- 创建工作台时原生注入课堂上下文；
- 平台统一持久卷生命周期；
- 工作台停止/释放前调用简报终结协议；
- BAMS 管理页增加简报跳转。

阶段 3 不是阶段 1–2 的前置条件。

## 17. 验收标准

### 17.1 插件独立验收

- 连续采集 45 分钟不因失活清理而中断；
- 网络断开后事件保留，恢复时严格按序补传且不重复；
- 页面关闭前已进入 IndexedDB 的事件可在重开后恢复；
- 5 分钟内重开继续原会话；
- 超过 5 分钟生成标记为部分数据的基础简报；
- AI 不可用时基础简报仍可生成；
- 单次普通粘贴不产生 AI 辅助警告；
- 10,000 条以上事件不会使原始日志丢失或整个简报失败。

### 17.2 平台联调验收

- 教师页面关闭时，学生摘要和简报仍写入服务端；
- 教师重开页面后恢复全班四态状态；
- 教师只看到自己课程的学生；
- 学生不能读取其他学生简报；
- 教师主界面不增加大量技术列；
- 原有环境管理页面和字段行为不回归；
- BAMS 容器释放后 FinColab 简报仍可查看；
- BAMS 详细日志保留与否有明确持久卷验证证据。

## 18. 明确阻塞项与交接需求

进入平台联调前，平台团队必须提供或确认：

1. `【共享后端必需】` 可部署独立同步服务，或提供 FinColab 后端接入仓库；
2. `【共享后端必需】` 可信用户、课程成员和课堂关系的查询方式；
3. `【BAMS 运维配置】` 插件结果目录的持久卷映射；
4. `【BAMS 运维配置】` BAMS 容器访问同步服务的 HTTPS/CORS/网络策略；
5. `【FinColab 前端小改】` 允许新增独立课堂巡视路由和学生简报入口；
6. 数据保留、教师查看详细代码证据和学生知情提示的业务规则。

在这些条件未确认前，可以完成插件可靠性改造和本地契约测试，但不得宣称已完成 FinColab 教师端实时同步。

## 19. 回滚与兼容

- 新课堂监控对象与原有课程/环境对象分离，不需要破坏性数据库迁移；
- FinColab 新入口可由功能开关关闭；
- 未携带课堂票据时，插件继续作为单容器本地模式运行；
- 同步服务不可用时，插件降级为本地保存并显示“等待同步”；
- 旧 BAMS 镜像不安装新插件时，原有 Notebook 和环境管理功能不受影响；
- 回滚 FinColab 前端时，只移除新路由和入口，不回退原有字段。

## 20. 设计停止点

本文确认后，下一阶段只制定实施计划，不直接修改平台或部署。实施计划必须将插件、同步服务、FinColab 前端和 BAMS 运维配置拆成独立工作包，并分别标明代码仓库、负责人、验证命令、部署顺序、回滚方式和当前阻塞项。
