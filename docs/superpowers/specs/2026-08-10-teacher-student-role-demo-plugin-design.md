# 教师端/学生端演示插件 0.3.0 设计

日期：2026-08-10

## 1. 背景与目标

现有编程行为监控分析插件已作为 JupyterLab 4 预构建扩展和 Jupyter Server 扩展安装到 BAMS 工作台镜像。目标平台前端已经区分 `student`、`teacher` 和 `admin`，并通过 BAMS 接口创建算法开发任务、启动工作台和打开 JupyterLab。

本轮只修改插件，将同一个 wheel 以运行时配置切换为教师端或学生端，用于下周演示。教师端负责方案配置、AI 建议、本地发布和本地结果查看；学生端负责执行演示任务、行为采集以及查看自己的日志和结果。

本轮版本定为 `0.3.0`。角色分流和学生端独立界面属于新增功能，不作为 `0.2.2` 的补丁版本发布。

## 2. 当前基线与实施前提

当前仓库 `main` 位于 `420f099`。已经部署和验证的 `0.2.2` 自动补全修复位于独立分支 `fix/ui-hotfix-0.2.1` 的 `a821218`，尚未合入 `main`。实施 `0.3.0` 前必须在隔离 worktree 中明确继承或整合该已验证修复，不能从缺少修复的旧基线重新实现并造成回归。

BAMS 当前工作台已确认使用 `PyTorch-2.5.1-JupyterLab4-BehaviorAudit-0.2.2` 镜像。目标平台前端仓库已有角色路由和 BAMS 工作台启动链路，但本轮不修改该仓库。

## 3. 范围、禁止项与停止点

### 3.1 允许范围

- 一个 `0.3.0` wheel 同时包含教师端和学生端；
- 插件服务端读取运行时角色环境变量；
- 插件配置接口返回角色和能力列表；
- 教师端/学生端界面按能力加载；
- 教师专用服务端接口执行角色校验；
- 学生端内置本地演示任务和缺失任务兜底；
- 现有方案、监控、日志、AI 分析和安全自动补全逻辑的必要适配；
- 自动化测试、wheel、Docker 配置片段、安装/验证/卸载/回滚说明和演示文案。

### 3.2 禁止范围

- 不修改 BAMS 后端或管理页面；
- 不修改 `lab-platform-frontend`；
- 不实现教师容器向学生容器自动下发方案；
- 不实现学生结果回传、班级汇总或正式多租户授权；
- 不调用真实或付费 AI 进行本地自动化验收；
- 不推送镜像、不登记 BAMS 框架、不部署目标平台；
- 不在 wheel、镜像、文档或日志中写入 API Key、Cookie、token 或真实学生数据；
- 不顺手重构与角色分流无关的模块。

### 3.3 停止点

代码、测试、`0.3.0` wheel、教师/学生部署片段和交付文档完成并通过本地无付费验收后停止。真实 BAMS 镜像构建、镜像推送、平台登记和真实 AI 验收由获得授权的平台管理员执行。

## 4. 已选方案与取舍

采用插件服务端环境变量方案：

```text
BEHAVIOR_AUDIT_ROLE=teacher
BEHAVIOR_AUDIT_ROLE=student
```

Jupyter Server 启动时读取并固定角色。只接受 `teacher` 和 `student`；缺失、空值、大小写异常以外的非法值都安全回退为 `student`。角色发生变化后必须重启 Jupyter Server 才生效。

不使用浏览器 URL、查询参数或 `localStorage` 决定角色，因为这些值可被用户修改且容易残留。不要求为教师端和学生端维护两个 wheel，因为两套制品会增加版本漂移、部署和回滚成本。

本轮是独立容器演示版。教师端的“发布”表示当前容器内方案已确认；学生端使用 wheel 内置演示任务或本地预置方案，不表示跨容器下发。

## 5. 组件边界

### 5.1 角色配置解析器

角色配置解析器只负责读取、规范化和验证 `BEHAVIOR_AUDIT_ROLE`，输出：

```json
{
  "role": "teacher",
  "capabilities": [
    "plan:write",
    "plan:publish",
    "ai:configure",
    "monitor:control",
    "logs:read",
    "analysis:read"
  ],
  "fallbackApplied": false
}
```

学生角色只获得监控、任务读取、日志读取和个人分析读取能力。配置接口不得返回 API Key、服务端路径或其他秘密。

### 5.2 服务端权限层

前端隐藏入口只改善体验，不作为权限边界。所有会改变教师方案、AI 配置或发布状态的接口必须在服务端再次检查能力。学生调用教师接口返回 `403` 和稳定、安全的错误码，不执行部分写入。

现有监控、日志和个人分析接口对两种角色开放；它们仍继承当前 Jupyter 会话认证和单容器文件访问边界。

### 5.3 教师端界面

教师端保留：

- 创建、修改、排序和删除考核方案；
- 配置 AI 服务；
- 生成、采用和编辑 AI 知识点建议；
- 对缺失的名称、说明或观察依据执行安全自动补全；
- 本地测试并发布方案；
- 启动/停止本地演示监控；
- 查看本容器的操作日志、过程日志和 AI 分析结果。

教师端沿用现有“编程行为分析”入口和三步方案流程，避免为角色分流重做整个界面。

### 5.4 学生端界面

学生端只显示：

- 当前演示任务的名称、说明和观察重点；
- 开始/停止行为监控；
- 采集事件数、有效观察时长和分析状态；
- 自己的操作日志、过程日志和 AI 分析结果；
- 分析失败后的“重新分析”。

学生端不渲染方案创建、方案发布、AI 服务配置、教师高级数据或管理入口。侧边栏使用正常方向的中文标签，不再依赖导致倒立文字的整体旋转。

### 5.5 本地演示任务提供器

学生端先尝试读取当前容器内有效的本地预置方案；没有有效方案时创建只读的内置演示任务。内置任务只提供演示所需的题目、知识点名称、说明和观察依据，不包含真实教师或学生数据。

内置任务不能覆盖已有有效方案。自动创建必须幂等，刷新页面或重复启动不产生多份任务。

### 5.6 本地数据层

继续使用现有单容器文件和日志机制。三份会话日志保持：

- `operation_log.json`；
- `process_log.md`；
- `analysis_log.json`。

教师与学生容器之间不共享目录、数据库或消息。所有用户可见文案必须明确这是演示版的本地结果，不能暗示班级数据已经同步。

## 6. 数据流

### 6.1 插件启动

1. Jupyter Server 读取并固定角色；
2. 插件前端请求自己的配置接口；
3. 配置接口返回角色、能力和是否发生安全回退；
4. 前端根据能力注册教师端或学生端命令、侧边栏和内容组件；
5. 配置请求失败时进入安全学生壳层，不显示教师功能，并提供重新加载。

### 6.2 教师演示

```text
创建方案
→ AI 生成建议
→ 采用或编辑
→ 自动补全缺失字段
→ 本地测试
→ 本地发布
→ 运行一次演示代码
→ 查看本地日志和分析结果
```

采用 AI 建议后，名称、说明或观察依据缺失时使用安全默认值补齐。前端进入下一步前仍执行规范化校验；自动补全不是跳过数据验证。

### 6.3 学生演示

```text
读取本地或内置演示任务
→ 开始监控
→ 输入、修改、粘贴和运行代码
→ 停止监控
→ 生成操作日志与过程日志
→ AI 分析
→ 查看个人结果
```

分析失败不影响已经保存的行为证据和两份非 AI 日志。重新分析复用已完成会话，不要求学生重新演示整个过程。

## 7. 异常处理

| 场景 | 行为 |
| --- | --- |
| 角色缺失或非法 | 回退到学生端，配置接口标记 `fallbackApplied=true`，服务端记录不含秘密的警告 |
| 配置接口失败 | 不显示教师功能，显示安全错误和“重新加载” |
| 学生调用教师接口 | 返回 `403`，不产生部分写入 |
| 本地演示任务缺失 | 幂等创建内置任务 |
| 内置任务创建失败 | 显示明确错误，禁止开始无任务监控 |
| 日志部分缺失 | 显示已有日志和缺失项状态，不让整个页面失败 |
| 分析失败或超时 | 结束加载态、保留日志、显示稳定原因和“重新分析” |
| AI 建议字段不完整 | 规范化并自动填充安全默认值，再执行完整校验 |
| AI 未配置 | 教师端提示配置；学生端保留非 AI 日志并显示分析暂不可用 |
| 角色环境变量修改 | 当前进程不热切换，重启 Jupyter Server 后生效 |

错误响应不得包含 API Key、Provider 原文、Cookie、token、服务器绝对路径或堆栈详情。

## 8. 安全与兼容性

- 默认角色为学生，遵循失败关闭；
- 能力由服务端产生，前端不自行推断；
- 教师写操作由服务端强制校验；
- AI Key 只保存在现有插件服务端配置路径，配置接口和学生接口不返回 Key；
- 前端 API 地址继续使用 Jupyter `baseUrl`，兼容 BAMS 的 `/notebook_<uuid>/...` 动态前缀；
- 不新增独立端口，不修改 BAMS WebSocket 或 Jupyter 内核连接配置；
- 不改变现有日志格式和会话目录布局，降低 `0.2.2` 升级风险；
- 旧镜像不设置新环境变量时会安全进入学生端，因此教师镜像必须显式配置 `teacher`。

## 9. 测试策略

实施遵循 TDD，先增加失败测试，再写最小实现。

### 9.1 后端测试

- `teacher`、`student`、缺失值、空值、大小写和非法值的解析；
- 非法值安全回退且不获得教师能力；
- 配置接口只返回公开字段；
- 学生访问每个教师写接口均返回 `403`；
- `403` 路径无文件或配置部分写入；
- 内置演示任务创建幂等且不覆盖有效方案；
- 现有日志、AI 分析、自动补全和重试逻辑回归通过。

### 9.2 前端测试

- 教师角色只显示教师功能；
- 学生角色不创建教师命令、菜单和组件；
- 配置加载失败时不短暂闪现教师界面；
- 学生端完整监控与日志状态流；
- 分析失败退出加载态并显示重试；
- 缺失字段自动补全后可以进入下一步；
- 侧边栏中文标签方向正常；
- 刷新和首次打开不显示旧方案或旧日志。

### 9.3 构建和隔离验收

- 后端全量 `pytest`；
- 前端单元测试、lint 和生产构建；
- wheel 内容检查和 SHA-256；
- 在两个干净环境中安装同一个 wheel，分别使用 `teacher` 和 `student`；
- 未设置角色的第三个干净环境验证学生回退；
- Jupyter Server 扩展、JupyterLab 扩展和内核连接保持正常；
- 自动化测试不联网、不调用真实或付费 AI。

## 11. 镜像配置片段

两个镜像使用完全相同的 wheel，仅角色不同：

```dockerfile
# 教师镜像
ENV BEHAVIOR_AUDIT_ROLE=teacher
```

```dockerfile
# 学生镜像
ENV BEHAVIOR_AUDIT_ROLE=student
```

AI Base URL、模型和 Key 仍按现有运行时配置注入，不写入 Dockerfile。学生镜像可以保留服务端 AI 分析能力，但不得暴露 AI 配置 UI 或 Key。

## 12. 验收标准

- 同一个 `0.3.0` wheel 在教师和学生配置下分别显示正确界面；
- 未配置或错误配置角色时只能进入学生端；
- 学生端看不到教师入口，教师写接口全部返回 `403`；
- 教师完成“AI 建议 → 采用 → 自动补全 → 下一步 → 本地发布”；
- 学生完成“开始监控 → 运行代码 → 停止 → 生成日志 → 分析 → 查看结果”；
- 新容器首次打开不残留旧方案、旧日志或上次角色；
- 分析失败不会无限加载，可保留日志并重新分析；
- 安装插件后 Jupyter 内核与 WebSocket 正常；
- 交付目录包含 wheel、源码基线、校验和、配置片段、安装步骤和两套演示文案；
- 所有未执行的真实 BAMS、镜像仓库和真实 AI 验收被准确标记为未验证。

## 13. 回滚

回滚不依赖删除教学数据：

1. 停止使用 `0.3.0` 新镜像；
2. 切回已验证的 `PyTorch-2.5.1-JupyterLab4-BehaviorAudit-0.2.2` 镜像；
3. 如需原地软件回滚，卸载 `0.3.0` 并安装已归档且 SHA-256 已确认的 `0.2.2` wheel；
4. 重启 Jupyter Server；
5. 验证扩展列表、内核连接和一次无付费合成会话。

软件回滚不得自动删除持久化日志、方案或用户结果。数据清理需要单独授权。

## 14. 已知限制与后续阶段

本版是角色化演示插件，不是正式教师/学生协作系统。它不提供：

- 平台身份到插件角色的签名传递；
- 教师发布到学生容器；
- 学生结果回传教师；
- 班级统计、课程归属、正式权限审计；
- 跨工作台共享密钥或数据治理。

后续正式联动必须由平台或 BAMS 后端提供可信身份、课程/实验上下文和共享服务接口，再以独立设计进入下一阶段。
