# VS Code 一键结束、分析与导出设计

日期：2026-08-12  
范围：`vscode-extension` 学生端会话结束流程

## 目标

把当前需要分别执行“结束监控”“生成 AI 会话分析”“导出会话”的流程收敛为一个课堂中容易理解的主操作，确保导出包稳定包含操作日志、过程日志和分析日志，同时不让 AI 或网络故障阻塞本地证据导出。

## 非目标

- 不修改 Jupyter/BAMS 插件。
- 不改变采集事件、课堂简报或教师方案的数据结构。
- 不移除现有独立命令；它们继续作为重试和故障恢复入口。
- 不自动上传或发送日志到教师端。

## 用户流程

学生端显示：

1. 默认选中的“自动生成 AI 分析”复选框。
2. 主按钮“结束监控并导出”。
3. 保留“导出上次会话”，便于取消目录选择或重新导出。

点击主按钮后依次执行：

1. 确认结束当前本地会话。
2. 将会话标记为 `completed`。
3. 生成 `operation_log.json`、`process_log.md` 和 `classroom_brief.json`。
4. 若启用自动 AI，则调用已配置的 AI 服务生成分析。
5. AI 未配置或调用失败时，生成结构化失败说明，不阻塞后续导出。
6. 弹出文件夹选择器并导出完整会话目录。
7. 显示成功、跳过 AI 或 AI 失败但已导出的明确结果。

如果用户取消文件夹选择，会话和本地生成的日志仍然保留，可用“导出上次会话”重新选择位置。

## 文件与兼容性

导出目录继续使用会话 ID 作为文件夹名称。核心文件为：

- `operation_log.json`
- `process_log.md`
- `analysis_log.json`
- `classroom_brief.json`
- `plan_snapshot.json`
- `manifest.json`

内部存储沿用现有 `ai_analysis` artifact kind，避免迁移历史数据；仅将导出文件名统一为 `analysis_log.json`。历史会话若已有 AI artifact，可以直接按新名称导出。

`analysis_log.json` 包含两种合法状态：

- `status: "completed"`：包含 AI 维度结论、证据与分析来源。
- `status: "failed"` 或 `status: "skipped"`：包含安全处理后的原因和重试提示，不包含 API Key 等敏感配置。

## 模块边界

- 命令注册层：增加一键工作流命令及确认规则。
- 工作流层：串联结束、简报、可选 AI 和导出；返回可展示的结果，不操作 UI HTML。
- AI 层：复用现有 `AiClient.analyzeSession`。
- 存储层：复用现有 session artifact，不新增数据库或迁移。
- 导出层：继续生成哈希清单，并将 AI artifact 导出为 `analysis_log.json`。
- 侧边栏：只负责复选框、按钮与状态提示。

## 错误处理

- 本地会话结束或本地日志生成失败：停止工作流并提示重试，不弹出导出成功。
- AI 未配置、超时、订阅异常或网络失败：写入失败/跳过说明后继续导出。
- 用户取消导出位置：不视为数据丢失，提示可稍后导出。
- 目标目录已有同名非空会话目录：保持现有防覆盖规则，提示选择其他位置。
- 错误文件和界面提示不得包含 API Key、Authorization 请求头或完整敏感响应。

## 验收标准

1. 活动会话点击一次主按钮后完成会话、生成本地日志并进入目录选择。
2. AI 成功时，导出包包含内容完整的 `analysis_log.json`。
3. AI 未配置或失败时，导出仍完成，`analysis_log.json` 明确记录 `skipped` 或 `failed`。
4. 取消目录选择后可以用“导出上次会话”再次导出。
5. 原有独立命令仍可使用。
6. manifest 中所有文件哈希校验通过。
7. 单元测试覆盖成功、AI 失败、取消导出和防止敏感信息泄漏；完整测试、lint、类型检查和打包通过。

## 回滚

该功能不迁移已有数据。回滚时恢复旧侧边栏入口和旧导出文件名即可；现有会话数据与旧命令仍保持可用。
