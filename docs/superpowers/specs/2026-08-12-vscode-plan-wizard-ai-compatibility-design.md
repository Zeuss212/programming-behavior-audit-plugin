# VS Code 方案向导与 AI 兼容性设计

## 1. 背景与目标

当前 VS Code 教师端通过连续的单行输入框发布方案或输入 AI 题目。长题目难以阅读和修改，AI 建议生成后还会直接发布，教师缺少统一的复核界面。当方舟兼容接口返回 HTTP 400 时，扩展丢弃服务端错误详情，无法区分模型、参数或响应格式兼容问题。

本轮目标是：

- 将“手动发布方案”和“生成 AI 建议”合并为与 Jupyter 版一致的三步向导。
- 提供足够大的题目输入区、可编辑的 AI 建议和发布前复核。
- 改善 OpenAI 兼容接口的 JSON 输出兼容性，并展示脱敏后的可操作错误。
- 保持现有方案 JSON 契约、学生端导入和导出流程不变。

## 2. 范围与非目标

本轮只修改 `vscode-extension` 及其测试、文档和交付包。不修改 BAMS、Fincolab 或 Jupyter 后端，不新增服务端数据库，不改变学生端采集范围，也不将 API Key 移出 VS Code SecretStorage。

## 3. 交互设计

### 3.1 入口

教师端保留一个主操作“创建考核方案”。旧的“发布方案”和“生成 AI 建议”命令作为兼容入口，两者都打开同一个方案向导，避免已有命令、快捷键或演示文档立即失效。

### 3.2 第一步：输入题目

- 独立 Webview Panel 提供多行题目编辑区，支持长文本、示例输入输出和换行。
- 显示字符数和上限，不允许空题目进入下一步。
- 输入变化后延迟保存到当前工作区的草稿状态。
- 页面不要求先打开编辑器文件；但没有本地文件夹时明确说明草稿的保存范围。

### 3.3 第二步：确认知识点

- 教师可选择“生成 AI 建议”或“手动添加”，AI 不是发布前置条件。
- AI 请求过程显示进度、取消和重试状态，不清空已有草稿。
- 建议以可编辑卡片展示，每张包含名称、说明和观察依据，支持添加、删除和排序。
- AI 返回的缺失字段使用安全默认值补齐，并标记“建议复核”。默认值只描述可观察的编辑或运行证据，不表达评分或能力判断。
- 进入下一步前，校验至少一个知识点，且名称、说明和观察依据均不为空。

### 3.4 第三步：确认并发布

- 以只读摘要展示题目、知识点、观察依据和测试建议。
- 教师可返回前两步修改。
- 只有显式点击“发布方案”才调用现有 `PlanRepository.publish`。
- 发布成功后显示方案版本，并提供“导出方案”和“返回教师端”。

## 4. 组件边界与数据流

### 4.1 `PlanWizardPanel`

负责 Webview Panel 生命周期、CSP、资源 URI、向导 HTML 与扩展主机之间的消息交换。它不直接访问文件系统、SecretStorage 或 AI 服务。

### 4.2 `PlanDraftStore`

使用 VS Code `workspaceState` 按工作区保存草稿。草稿包含内部版本、题目、知识点、测试建议、当前步骤和更新时间。加载旧草稿时执行校验；损坏或未知版本的草稿不进入发布流程。

### 4.3 Webview 消息协议

页面发送有类型的 `saveDraft`、`requestSuggestion`、`publishDraft`、`exportPlan` 和 `closeWizard` 消息。扩展主机校验所有输入后才调用存储、AI 或方案仓库。主机返回 `draftLoaded`、`suggestionReady`、`requestFailed` 和 `planPublished` 状态。

### 4.4 发布契约

向导草稿最终转换为现有 `PublishPlanInput`。不新增对外字段，不更改方案 schema 版本、哈希生成方式或学生端导入校验。

## 5. AI 兼容与错误处理

### 5.1 结构化输出

系统提示词明确要求“只返回 JSON”，并描述方案建议或会话分析的必需字段。现有 AJV schema 继续作为信任边界，服务端返回内容未通过校验时不直接进入草稿。

### 5.2 `response_format` 兼容降级

第一次请求保留 `response_format: { type: "json_object" }`。当服务返回 HTTP 400，且脱敏错误明确指向 `response_format`、JSON mode 或结构化输出不受支持时，客户端仅重试一次，去掉 `response_format` 但保留严格 JSON 提示词和 schema 校验。其他 400 不自动降级，避免把模型名、额度或其他请求错误误判为格式问题。

### 5.3 脱敏错误

非成功响应最多读取受限大小的 JSON 或文本错误体。只提取服务端 `error.code`、`error.type`、`error.param` 和短 `error.message`，去除控制字符、Bearer 值、疑似密钥、绝对路径和过长文本。用户界面显示状态码和脱敏原因，详细日志也不包含请求头、API Key 或完整题目。

### 5.4 失败保护

AI 超时、网络失败、鉴权失败、限流或返回无效 JSON 时，保留草稿、恢复生成按钮并允许重试或手动继续。只有会话分析保留现有的短重试策略；方案建议不对一般 400 或鉴权错误自动重试。

## 6. 可用性、可访问性与主题

- 使用 VS Code 主题变量，同时支持深色和浅色主题。
- 向导步骤使用文字和状态，不单独依赖颜色。
- 表单控件具有明确 label、错误文本和键盘焦点顺序；异步状态通过 `aria-live` 通知。
- 主要操作保持固定层级：上一步、下一步、生成 AI 建议、发布方案不因内容长度难以寻找。
- 小窗口下保持单列布局；大窗口只在有助于复核时并排表单和辅助信息。

## 7. 测试策略

- AI 客户端单元测试：正常 JSON、400 错误解析和脱敏、只对明确格式不兼容的响应降级一次、其他 400 不降级、无效 JSON 仍被 schema 拒绝。
- 草稿存储单元测试：保存和恢复、未知版本、损坏草稿和工作区隔离。
- Webview 协议和 HTML 测试：三步标识、大文本区、可访问标签、主要按钮、CSP 和无内联脚本。
- 命令集成测试：旧入口打开新向导、AI 建议不直接发布、显式发布仍生成可导入的原契约。
- 交付验证：运行项目统一的 lint、类型检查、单元测试、构建和 VSIX 打包，然后在 VS Code Extension Development Host 完成一次手动三步冒烟。

## 8. 兼容、迁移与回滚

- 保留旧命令 ID，只改变它们的交互入口。
- 现有已发布方案和学生会话不迁移。
- 新草稿是内部状态，不写入旧方案目录。
- 回滚时安装上一个 VSIX 即可；旧版本会忽略新草稿键，已发布方案仍可用。

## 9. 验收标准

1. 教师可在独立大页面中输入多行长题目，关闭并重新打开后草稿仍在。
2. 手动编辑和 AI 生成共用同一个三步向导。
3. AI 建议可编辑、删除、排序和复核，生成完成后不会自动发布。
4. 格式不兼容的 400 可安全降级一次；其他 400 显示脱敏原因，不泄露密钥、绝对路径或完整题目。
5. 所有失败路径保留草稿，且不阻断教师手动完成方案。
6. 发布后的 JSON 契约与当前学生端导入完全兼容。
7. 项目 lint、类型检查、单元测试、构建和 VSIX 打包通过，并留存手动冒烟记录。

## 10. 停止点

本设计完成并经用户审核后，再编写实施计划。实现完成后停在“本地构建、测试和 VSIX 产物就绪”；未经新授权不推送远程、不部署外部平台、不操作付费 API。
