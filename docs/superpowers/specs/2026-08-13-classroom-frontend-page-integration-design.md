# FinColab 课堂方案页面接入设计

**日期：** 2026-08-13
**状态：** 已由用户确认，待实施计划审阅
**目标仓库：** `lab-platform-frontend` 的新隔离 worktree；不修改现有带用户未提交文件的前端工作区。

## 目标与范围

将已有“实验管理”中的一个教师实验作为一节课堂的载体，形成可见的教师发布、学生接受、
学生监控与教师查看单份简报的闭环。教师不再为了监控课堂另建实验；学生不再拥有方案创建或
发布入口。

本轮包含：

- 教师从已有实验卡片进入课堂方案配置、发布、巡视和学生简报；
- 学生在已有项目列表中接受自己的课堂任务、查看状态并进入工作台；
- 学生工作台 URL 统一为 BAMS HTTPS `https://14.103.139.131:40037`，一次性票据只放在
  fragment 的 `behavior_ticket`，不进入 query；
- 方案绑定 parent experiment；学生任务绑定其 child algorithm/workbench；
- 功能开关关闭时，原有“创建实验”、学生项目和普通工作台入口不变。

本轮不包含：真实服务器部署、镜像推送、数据库迁移、课程 allowlist 开启、真实 AI 调用，
以及自动预加载全部原始日志。

## 方案比较与决策

已确认使用“实验卡片小入口 + 独立课堂页面”的方案：

- 在每张已有实验卡片显示“课堂方案”入口；卡片保留实验摘要，不承载长表单或全班表格；
- 独立页面依次承载课堂方案、巡视和学生简报，避免弹窗因知识点、时间和结果信息过长而
  难以阅读；
- 不增加与实验脱离关系的顶级课堂入口，避免教师先选课堂再寻找对应实验。

## 页面与路由

### 教师端

1. `AdminProjectsView` 的实验卡片在开关开启时显示“课堂方案”。入口携带 `courseId` 和
   `parentAlgorithmId`，进入 `AdminClassroomPlanView`。
2. 方案页面是三步向导：
   - 教学目标与知识点；
   - 上课、下课时间和学生可见采集说明；
   - 发布确认，明确学生会在实际下课后 15 分钟自动收口。
3. 发布后显示不可变的方案版本和“进入课堂巡视”。已开始的学生会话继续使用当时版本；
   后续修改必须形成新草稿，不能静默改写历史课堂。
4. `AdminClassroomMonitorView` 展示学生状态、最后活动、提交情况与简报入口。SSE 连续三次
   失败时退化为 10 秒轮询；状态同时使用文字和图标。
5. `AdminStudentBriefView` 显示一份教学简报：掌握概览、知识点矩阵、最多三项主要问题和
   教师复核。证据清单先展示索引，教师显式点击某条证据后才请求临时访问 URL。

### 学生端

1. `StudentProjectsView` 在开关开启且存在本人课堂任务时显示“课堂任务”状态投影；学生
   无法查看方案编辑、发布、AI 密钥或其他学生数据。
2. `StudentAssignmentView` 显示题目、知识点、采集范围、时间、教师查看范围及自动收口规则；
   学生明确接受后才能申请一次性票据。
3. 票据申请成功后，前端把现有 BAMS workbench 路径规范为 HTTPS 40037，并以 fragment
   加入 `behavior_ticket` 后跳转。申请失败不打开裸工作台。
4. `StudentSubmissionView` 展示本人监控与提交状态：待接受、已就绪、监控中、暂时离线、
   提交中、证据补传中、已完成、部分完成。活动状态每 10 秒轮询；终态停止轮询。

## 模块边界与数据流

新增 `src/modules/classroom-monitoring/`，其中 API、类型、功能开关、方案草稿、票据 URL、
课堂巡视状态和学生任务状态分离；页面仅负责组合模块和展示。课堂 API 使用独立的
`VITE_CLASSROOM_SYNC_PREFIX`（默认 `/classroom-api`），复用当前登录 Bearer Token，绝不
修改现有 BAMS API client 的基础地址。

数据流为：

1. 教师保存草稿并发布，课堂同步服务为对应课程学生创建任务；
2. 学生接受自己的任务，获取一次性票据并从 40037 打开工作台；
3. 插件通过同步服务恢复会话、上传证据和提交简报；关闭浏览器页面不会新建会话或第二份
   逻辑简报；
4. 学生手动提交，或实际下课后 15 分钟由服务端自动收口；
5. 教师通过课堂状态 API 和事件流读取状态及简报，原始日志保持后端私有。

## 权限、错误与回滚

同步服务负责最终授权；前端角色判断和隐藏按钮不构成安全边界。教师仅可管理自己课程中
绑定的实验、学生任务与简报；学生只能读取和操作自己的任务。403、404、409 和 503 必须
保留稳定错误 code、`retryable` 和 `request_id`，用可理解的提示和重试动作呈现，不能仅显示
空白页或把未知状态误报为已提交。

`VITE_CLASSROOM_MONITORING_ENABLED=false` 是默认值。关闭开关时，所有课堂入口、菜单和
启动拦截消失，原有实验创建和工作台路径完全保留；这也是前端即时回退方式。回退不删除
已发布方案、简报、证据或学生会话。

## 验收标准

- 开关关闭：现有 `/admin/projects`、`/student/projects`、`/student/launch/...`、实验创建和
  环境状态行为不变；
- 开关开启：教师可从已有实验完成完整方案输入、发布并查看课堂状态；学生只能接受自己的
  任务并获得 40037 fragment 票据 URL；
- 完整知识点输入不得误报缺项，错误提示必须定位字段；重复发布和 409 冲突不会生成重复方案；
- 学生不能看见或调用教师写接口；工作台票据不出现在 query、日志或页面正文；
- 误关后可恢复原会话，学生只有一份简报；教师可查看简报而不自动加载原始日志；
- 所有新页面具备 loading、error、empty 与 partial 状态，键盘可完成表单、发布、接受和
  简报证据展开；在 320、768、1024、1440 px 下保持可用；
- Vitest、类型检查、只读 lint、生产构建和本地浏览器关键路径验证通过后，才可构建候选镜像；
  部署、推送与开关开启仍需要单独授权。
