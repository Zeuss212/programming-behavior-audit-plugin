# 本地 GLM Coding Plan 课堂 AI 分析设计

**日期：** 2026-08-15  
**状态：** 已确认，待实现  
**范围：** 本地课堂互动演示；不合并 `main`、不推送、不部署。

## 目标

在本地课堂演示中接入 GLM Coding Plan，同时支持：

1. 教师为课堂方案生成可编辑的 AI 建议；
2. 学生提交课堂简报后，异步生成教师可读的 AI 教学分析。

学生提交必须始终保存确定性基础简报。AI 上游故障、超时或非预期输出不能阻止提交，也不能使教师失去已提交的简报。

## 非目标

- 不连接生产 FinColab、BAMS、真实课堂数据或生产身份系统。
- 不让 Vue 前端、Jupyter 插件、浏览器或学生环境持有 AI Key。
- 不把 AI 结果用作自动评分、纪律判断或最终评价。
- 不在本阶段合并主分支、推送远程仓库或部署。

## GLM Coding Plan 配置

服务端沿用现有 OpenAI Chat Completions 兼容适配器。Coding Plan 的默认本地配置为：

```dotenv
CLASSROOM_AI_BASE_URL=https://open.bigmodel.cn/api/coding/paas/v4
CLASSROOM_AI_MODEL=glm-5.2
CLASSROOM_AI_API_KEY=
CLASSROOM_AI_TIMEOUT_SECONDS=30
```

适配器将 Base URL 规范化为 `/chat/completions`。仓库提交无密钥的 `.env.ai.example`；实际 Key 只能手工写入被 Git 忽略的 `deploy/classroom/local-demo/.env.ai`。Compose 启动器仅在该文件存在时向本地 `sync-api` 与异步 worker 注入这些变量。

Base URL 继续只接受无用户信息、查询串或片段的 HTTPS 地址。运行日志、错误响应、前端页面和测试输出均不得包含 API Key。

官方参考：

- [智谱 HTTP API 调用](https://docs.bigmodel.cn/cn/guide/develop/http/introduction)
- [GLM Coding Plan 快速开始](https://docs.bigmodel.cn/cn/coding-plan/quick-start)

## 组件和数据流

```text
教师方案输入 ──> sync-api 方案建议适配器 ──> GLM ──> 可编辑建议

学生 Jupyter 插件 ──> sync-api 提交简报
                                      ├─> 立即保存基础简报 + pending
                                      └─> 持久化 AI 分析任务
本地 worker ──> 领取任务 ──> GLM ──> 保存 AI 分析 + ready
教师监控/简报页 <──────────────────────────────┘
```

### 方案建议

现有教师方案建议接口继续发送教师主动填写的课程标题和任务说明。模型返回严格校验的 JSON 方案草稿；教师必须主动应用并发布，模型不能自行发布课堂。

### 提交后分析

`BriefService` 保存学生提交的原有简报后，若 AI 已完整配置，则将简报状态写为 `pending` 并创建一个持久化任务。任务的唯一归属为当前简报版本：重复提交会产生新的基础简报及新任务，不覆盖已归档版本。

Worker 从数据库领取待执行任务，调用服务器端 GLM 适配器，再以新的简报版本写入分析结果。读取最新简报的教师因此会看到当前状态和内容；服务重启或教师刷新不会丢失任务或结果。

## 最小数据模型

新增持久化 `brief_analysis_jobs`，包含：

- 任务 ID、关联的简报版本、状态、尝试次数、下次尝试时间；
- 锁定信息与完成时间；
- 安全的内部失败分类，不保存 Key 或完整上游响应。

简报内容在既有确定性字段外增加可选 `ai_analysis`：

- `learning_overview`：对已提交过程的简短概述；
- `evidence_based_observations`：只基于传入摘要的学习观察；
- `teaching_suggestions`：下一步教学建议。

所有字段有长度、数量和 JSON 结构上限；模型响应必须通过 Pydantic 校验才能保存。原有学生提交摘要永远保留，不由 AI 覆写。

## 隐私和提示词边界

提交给 GLM 的数据只包含经过现有简报生成器压缩后的标题、课程知识点、过程概览和问题摘要。不得发送原始代码、原始运行日志、证据对象地址、课堂票据、插件令牌、访问令牌或 API Key。

系统提示要求模型只返回指定 JSON、基于提供材料做辅助教学分析、避免推断未提供的个人属性，并声明结果不可直接作为自动评分结论。所有输入被作为数据封装，模型文本不能改变该服务的权限、任务状态或发布权限。

## 状态和错误处理

| 状态 | 含义 | 教师界面 |
| --- | --- | --- |
| `not_requested` | 没有配置 AI 或本次无需分析 | 显示“未配置 AI 分析” |
| `pending` | 基础简报已保存，分析任务待处理或重试中 | 显示“AI 分析生成中” |
| `ready` | 合规的 AI 分析已保存 | 显示“AI 分析已完成”并展示分析卡片 |
| `unavailable` | 三次处理后仍无法生成 | 显示“AI 分析不可用”，基础简报仍可读 |

超时、网络异常、4xx/5xx、无效 JSON 和不符合结构的模型响应均使用统一上游错误分类。Worker 最多尝试三次；最终失败标为 `unavailable`。学生提交路径不会等待模型响应，教师读取接口也不会因分析失败返回错误。

## 教师界面

教师监控表新增 AI 状态列，让教师无需逐个打开简报也能判断分析是否已生成。学生简报页保留确定性教学简报，并在其下显示独立的“AI 教学分析”卡片；该卡片始终标注“辅助分析，不自动评分”。

`pending`、`unavailable` 与 `not_requested` 显示状态说明而非空白区域。已完成课堂仍通过既有“课堂管理 → 课堂监控 → 学生简报”入口查看，不要求重新配置方案。

## 验收与验证

自动化覆盖以下内容：

1. AI 配置为空、完整、部分缺失及不安全 URL 的行为；
2. Coding Plan 请求 URL、鉴权头、模型、请求边界和密钥不出现在错误信息中；
3. 严格 JSON 响应校验、持久化任务状态、三次重试及最终失败；
4. GLM 不可用时学生提交仍成功、教师仍读取基础简报；
5. 教师权限、监控状态列和四种简报 AI 状态的前端渲染；
6. 后端测试、前端测试、类型检查、构建和本地演示 smoke 测试。

真实 GLM 冒烟调用仅在用户手动创建本地 Key 文件并明确授权后执行，因为它会消耗 Coding Plan 套餐额度。常规 CI/本地回归均使用受控 HTTP Mock，不依赖真实 Key。

## 完成边界

完成本任务意味着两个独立 worktree 的本地实现、Mock 验证、配置样例和演示步骤齐备。真实 Key 的填写及任何产生套餐消耗的联调都作为单独的用户授权步骤；主分支与远程仓库保持不变。
