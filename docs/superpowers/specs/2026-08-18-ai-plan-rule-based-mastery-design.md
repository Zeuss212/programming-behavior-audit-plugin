# AI 方案规则驱动的知识点自动判定设计

## 目标

在教师点击“AI 生成建议”时，同时生成每个知识点的受限自动判定规则。学生提交课堂简报时，Jupyter 插件只在本地读取代码历史与运行事件，按这些规则产生知识点状态；课堂服务和教师端只接收状态与脱敏说明。

## 非目标

- 不把学生源代码、标准输出或 API 密钥上传给课堂服务或 AI。
- 不让 AI 在学生提交时临时评分，也不执行 AI 生成的代码、正则表达式或脚本。
- 不替代既有教师复核；教师复核仍是可审计且优先级更高的覆盖层。

## 规则模型

每个 AI 建议知识点新增 `automatic_evaluation`。该字段的 `requirements` 是非空数组，`mode` 固定为 `all`。每条 requirement 仅能使用下列白名单 `kind`：

- `successful_execution`：至少一次代码执行成功。
- `dict_literal_assignment`：Python AST 中存在字典字面量赋值。
- `dict_key_value_pairs`：存在至少两个键值项的字典字面量。
- `dict_subscript_access`：存在对已识别字典变量的下标访问。
- `dict_get_with_default`：存在已识别字典变量的 `.get()` 调用，并至少提供默认值。
- `print_call`：存在 `print()` 调用。
- `input_call`：存在 `input()` 调用。

AI 只能从白名单中组合规则，并提供面向教师的中文 `summary`。无法表达的知识点不带 `automatic_evaluation`，提交时显示“需要复核”，而不是被误判为“已掌握”。

## 数据流

1. 后端的 AI 方案建议接口要求模型返回知识点、说明和规则，并用 Pydantic 验证白名单。
2. 前端展示并随“使用本次建议”保存每个知识点的规则；手动新增的知识点没有规则。
3. 已发布计划把规则作为版本化 profile 的知识点字段同步到 Jupyter 插件。
4. 插件汇总本地 `cell_source` 和 `code_execution` 事件，解析 Python AST，生成布尔特征。代码解析失败只会使相应特征不满足。
5. 插件根据每个知识点的 `all` 规则产生：全部满足为 `mastered`；存在成功运行但只满足部分规则为 `partial`；无成功运行或无相关特征为 `not_demonstrated`；无有效规则、日志不完整或不可解析为 `review_required`。
6. 插件上传状态、证据引用和中文说明，不上传源代码。教师复核继续覆盖自动状态。

## 等价性与边界

规则检查 Python AST 的语义结构，不检查固定变量名、学生姓名、成绩数字或输出文案。因此 `records`、`grades` 等不同变量名，只要形成相同字典访问与安全查询结构，都会满足规则。规则不运行学生代码，也不凭单个字符串出现判定掌握。

## 验收标准

- AI 方案建议返回并验证受限规则；不支持的规则被拒绝。
- 含不同变量名、不同键和值的字典正确代码，成功运行后，对应知识点显示“已掌握”。
- 缺少 `.get(..., default)` 的代码不会通过该知识点；有成功运行时为“部分掌握”。
- 没有成功运行、缺少规则、代码无法解析或日志不完整时不显示“已掌握”。
- 教师复核状态仍覆盖自动状态。
