# Jupyter 证据约束 AI 教学分析设计

## 目标与演示边界

为 JupyterLab 学生提交和课堂教师端提供一个可解释的 AI 教学分析闭环。学生完成会话后，固定课堂简报必须先生成并始终可读；学生明确选择“生成 AI 建议”时，系统才构造并发送本次会话的私有分析输入。AI 只能依据该输入，对教师确认的每个知识点给出有事件编号支持的观察状态和教学建议。

本轮演示目标是：教师可编辑并生成课堂建议、发布课堂并监控；学生在 JupyterLab 编辑和运行代码后提交；教师端看到固定简报及可解释的 AI 教学分析。

本轮只修改以下链路：

- JupyterLab 学生侧边栏和其本地 Jupyter 后端；
- `services/classroom-sync` 的插件提交、私有 AI 任务、worker 和教师读取模型；
- `lab-platform-frontend-classroom-ui` 的教师简报显示；
- 覆盖上述行为的测试和本地演示验证。

不修改 VS Code 扩展、`teacher_brief.md` 导出、数值评分、自动评分规则或生产部署。现有 worktree 的未提交“教师课堂建议”和规则化掌握改动必须保留，不能覆盖或顺手重构。

## 阶段合同

- **允许操作：** 在现有 `codex/classroom-main-integration` 与 `codex/classroom-ui` worktree 中新增或修改本设计列出的 Jupyter、平台、教师前端和测试文件；仅对本地演示做只读检查。
- **禁止操作：** 不读取或记录 AI 密钥；不重置本地数据卷；不展示、持久化到教师简报或日志、或向教师 API 返回学生源码、绝对路径、原始输出和 Provider 原文；不实现或调整评分。
- **验收标准：** 固定简报在未授权、AI 失败和 AI 成功时均可用；代码快照仅在授权时离开 Jupyter 本地后端；所有成功 AI 结论逐知识点包含合法状态、允许的事件编号和教学建议；教师端只显示安全结论。
- **停止点：** 单元、集成、前端测试及构建通过后，先报告结果；重建或重启当前 Docker 服务、启动教师演示前端以及进行真实 Provider 调用需要作为单独的本地演示阶段处理。

## 方案选择

### 方案 A：继续使用当前泛化简报分析

只加强当前 `learning_overview`、观察列表和建议列表的提示词。这能最快生成文本，但无法表达每个知识点的状态，也没有可验证的事件编号或“未授权不发送快照”边界，因此不满足本轮要求。

### 方案 B：私有、版本化 AI 分析任务（采用）

固定简报和私有分析输入分开存储。固定简报仍是教师 API 的基础数据；AI 任务在学生授权后保存白名单输入，worker 仅从该输入调用模型，并将经过校验的安全结论追加为新的简报 revision。教师 API 永远不返回任务输入。该方案在隐私、失败隔离和可解释性之间取得最小实现范围内的平衡。

### 方案 C：在教师端实时读取原始行为和源码再分析

教师端可以获得更多上下文，但会把敏感代码和输出暴露到不必要的界面与接口，并将分析时间与监控页耦合。它违反最小披露原则，不采用。

## 架构与数据流

```text
Jupyter 学生侧边栏
  └─ 未勾选：提交固定简报 ─────────────────────────────┐
  └─ 勾选：向本地后端传递授权布尔值                    │
      └─ 本地后端从本会话日志构造白名单分析输入          │
          └─ 平台提交：固定简报 + 私有任务输入 ──────────┤
                                                          ▼
                                            StudentBrief（安全、教师可读）
                                            ClassroomBriefAnalysisJob（私有输入）
                                                          │
                                                          ▼
                                                AI worker → 严格校验
                                                          │
                                                          ▼
                                      新 StudentBrief revision（安全 AI 结论）
                                                          │
                                                          ▼
                                              教师监控面板（结论/事件编号）
```

### 学生授权与固定简报

学生侧边栏在提交控件旁提供默认未勾选的复选框：“生成 AI 教学建议（仅发送本次课堂的脱敏代码片段和过程证据）”。提交请求将 `request_ai_analysis` 作为布尔值传给本地 Jupyter 后端，而不是让浏览器取得平台 token 或读取本地原始记录。

无论该值为何，本地后端都先完成既有会话收口、证据补传和确定性固定课堂简报生成。未授权时不构造分析输入、不发送快照、不创建 AI job，平台状态为 `not_requested`。授权时，固定简报照常写入，平台创建状态为 `pending` 的分析 job；提交成功不等待模型。

### 私有分析输入

本地后端仅在 `request_ai_analysis=true` 时，从当前会话和已交付证据构造以下 allowlist：

```json
{
  "lesson": { "title": "…" },
  "knowledge_points": [{ "id": "…", "name": "…", "description": "…" }],
  "evidence_events": [
    { "event_id": "chunk-2#event-7", "kind": "edit", "description": "编辑了 Python 单元" },
    { "event_id": "chunk-2#event-8", "kind": "run_failure", "description": "一次运行未完成" },
    { "event_id": "chunk-3#event-11", "kind": "run_success", "description": "编辑后完成一次运行" }
  ],
  "code_snapshots": [{ "sequence": 3, "source": "…" }]
}
```

输入不包含文件名、绝对路径、运行输出、诊断文本、学生身份、Provider 响应或未选择的事件。快照在本地构造时删除已知路径形式和诊断残留、按单段及总长度截断；本轮实现以总计不超过 12,000 Unicode 字符为硬上限。事件文本使用事件类别和安全的过程描述，而非源码或输出。

平台把该输入放入 `ClassroomBriefAnalysisJob` 的私有 JSON 字段，不放入 `StudentBrief.payload`，也不从任何教师读取接口返回。数据库迁移为该私有字段提供非空默认的空对象，保证已有 job 和本地演示数据可迁移。worker 从 job 的私有输入读取，而非从教师可见简报反推源码。

### AI 输出契约和校验

模型必须只返回 JSON：

```json
{
  "knowledge_point_analyses": [
    {
      "knowledge_point_id": "KP_00000001",
      "status": "observed",
      "evidence_event_ids": ["chunk-2#event-7", "chunk-3#event-11"],
      "teaching_suggestion": "请让学生口述按键读取和安全查询的区别。"
    }
  ],
  "teacher_note": "本结论仅反映本次已授权的过程证据，需结合课堂交流复核。"
}
```

`status` 仅允许映射为教师中文界面的“已观察 / 部分观察 / 未观察 / 需教师复核”。每个输入知识点必须恰好对应一个输出项，输出不得新增或遗漏知识点。除“未观察”外，`evidence_event_ids` 必须非空，且每项都必须出现在 job 允许的事件集合中；“未观察”必须没有编号。服务拒绝包含代码围栏、绝对路径、存储 URL、原始输出痕迹或超长文本的模型结果。运行成功只是一项过程证据，提示词和验证规则均禁止将其视为答案正确性或固定分数。

校验通过后，worker 以新 revision 写入仅含上述安全结论的 `ai_analysis`。Provider 异常或契约校验失败按现有重试策略处理；耗尽后新 revision 标为 `unavailable`，保留原有固定简报和全部固定过程信息。

### 教师端显示

教师简报面板保留固定摘要、知识点和 AI 状态。`ready` 时增加“AI 教学分析”区块，以一行一个知识点显示：知识点名、中文观察状态、事件编号列表和教学建议，并标明“辅助分析，不自动评分；需教师结合课堂交流复核”。`pending` 显示生成中；`not_requested` 表示学生未授权；`unavailable` 表示不可用且固定简报仍然可读。

前端 API mapper 使用显式 allowlist 映射，而不是原样渲染。任何不符合契约的分析数据、绝对路径、URL、对象存储引用、源码或原始输出均不会进入 DOM。

## 模块边界

| 模块 | 责任 |
| --- | --- |
| Jupyter sidebar / local route | 收集明确授权；由本地后端而非浏览器构造输入。 |
| `SubmissionCoordinator` | 生成固定简报、筛选安全事件和受限快照，并提交安全 brief 与可选私有输入。 |
| plugin router / `BriefService` | 验证授权和输入的一致性，持久化安全 brief 与私有 job 输入。 |
| `BriefAnalysisJobService` | 仅从私有 job 输入调用模型，校验逐知识点结果，并安全地完成或失败任务。 |
| teacher read model / Vue panel | 只传递并渲染安全结论、状态和事件编号。 |

## 测试与演示验证

自动化测试先覆盖失败路径，再写生产实现：

1. Jupyter：默认未授权提交不携带分析输入；勾选后本地请求携带授权，不向浏览器暴露快照。
2. 本地协调器：未授权不构造或上传代码；授权输入只包含白名单字段、没有路径/输出，且总长度不超过 12,000。
3. 平台服务：未授权为 `not_requested` 且无 job；授权创建包含私有输入的 pending job；教师 brief payload 不包含输入。
4. AI worker：有效逐知识点结果变为 `ready`；未知事件、缺少知识点、空证据或不安全文本均被拒绝；失败后固定简报仍可读取且状态为 `unavailable`。
5. 教师前端：显示中文状态、事件编号和建议；不会渲染源码、路径、URL、私有 job 字段或 Provider 原文。
6. 回归：教师“AI 生成建议”现有单元/集成测试、课堂服务测试、Jupyter TypeScript 测试和教师前端构建。

本地演示阶段在明确批准后，先启动教师前端，再在不重置数据卷的前提下重建相关服务并执行“教师生成建议 → 发布 → 学生编辑/失败运行/修正运行 → 勾选授权提交 → 教师查看 pending/ready”的冒烟流程。真实模型调用只使用环境中已有的私有配置，不在输出、文件或提交中记录密钥。
