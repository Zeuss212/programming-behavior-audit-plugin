# 学生提交后即时评分简报设计

**日期：** 2026-08-18  
**状态：** 已确认，待实施

## 目标

学生在 Jupyter 课堂侧边栏提交本节简报后，立即看到一份简版结果，而不必等待课堂平台的教师端 AI 分析或后台同步。简版结果只呈现：

1. 本节完成情况（`已完成` 或 `部分完成`）；
2. 0–100 的综合评分；
3. 结果等级（80 分及以上为 `优秀`，60–79 分为 `合格`，低于 60 分为 `未达到合格线`）；
4. 一句固定的评分边界说明。

评分沿用 VS Code 扩展的“课题实践表现”口径，作为课堂过程性反馈；它不等同于答案正确性，也不自动替代教师复核。

## 非目标

- 不改变教师端的完整学生简报、知识点掌握结论或教师复核。
- 不改变异步 AI 分析、AI 配置、远端课堂服务或平台数据库。
- 不根据源码答案、题目测试或生成式 AI 判定分数。
- 不在实现或验证阶段重启当前正在使用的 Jupyter、Vite 或 Docker 服务。

## 用户流程

1. 学生在 Jupyter 中点击“提交本节简报”。
2. 插件停止采集、固化事件并写入本地 `classroom_brief.json`。
3. 学生提交接口返回后，侧边栏读取该本地简报。
4. 侧边栏只显示“本节课堂简报”卡片中的完成情况、综合评分与评分说明；远端证据补传不会阻止本地卡片显示。

若本地简报读取失败，沿用现有提交成功/补传提示并显示可重试的读取提示；不得伪造分数。

## 评分规则

总分为 100 分，采用 VS Code `teacherEvaluation.ts` 的三个维度：

| 维度 | 满分 | Jupyter 事件映射 |
| --- | ---: | --- |
| 运行验证 | 55 | `code_execution` 的 `success` / `failure` 结果与成功率 |
| 调试与修正 | 25 | 失败运行后是否出现编辑，且之后是否再次成功运行 |
| 任务推进 | 20 | 是否形成一次编辑后运行的完整工作闭环 |

Jupyter 当前不会持久保存 VS Code 的 `save` 事件。因此，VS Code 的“编辑 → 保存 → 运行”工作闭环在此映射为“编辑（`code_writing`、`code_deletion` 或 `code_paste`）→ 运行”。这是唯一必要的平台适配；其余分档沿用 VS Code：

- 没有可判定运行：运行验证为 0 分；
- 有运行但没有成功：运行验证为 15 分；
- 只有一次可判定运行：运行验证为 25 分；
- 成功率低于 50%：25 分；低于 80%：40 分；
- 至少三次可判定运行且成功率至少 80%：55 分；其余成功情况：40 分。

VS Code 在可判定运行少于三次时，最终等级最高为 B。数值版采用等价限制：可判定运行少于三次时，最终综合分最高为 **74**，避免少量运行得到高分。没有可判定运行时综合分为 **0**。综合分 **大于或等于 80 分为优秀**，**60–79 分为合格**，低于 60 分为未达到合格线。评分不使用窗口焦点或页面离开数据。

## 数据与接口

本地 `classroom_brief` 契约新增且必须包含：

```json
"student_summary": {
  "completion_status": "completed",
  "overall_score": 74,
  "performance_level": "qualified",
  "note": "评分仅基于本节编辑、运行和修正过程，不等同于题目答案正确性。"
}
```

- `completion_status`：`completed` 或 `partial`，由本地会话终态确定；
- `overall_score`：0–100 的整数；
- `performance_level`：`overall_score >= 80` 时为 `excellent`，60–79 时为 `qualified`，低于 60 时为 `not_qualified`；
- `note`：固定、无敏感信息的说明文本。

该字段随现有安全的 `GET /myextension/sessions/{session_id}/brief` 响应返回；不进入平台上传载荷，避免扩大教师端或远端契约。

## 前端展示

学生模式的侧边栏从提交成功或补传中状态读取本地简报。新卡片不展示运行次数、编辑时长、过程亮点、注意事项或教师端同步提示，只渲染：

```text
本节课堂简报
完成情况：已完成
综合评分：74 / 100
学习结果：合格（60–79 分）
评分仅基于本节编辑、运行和修正过程，不等同于题目答案正确性。
```

教师模式继续使用当前的完整本地简报视图，保持不变。

## 测试与验收

1. Python 单元测试覆盖：无可判定运行得 0 分；失败后编辑并成功运行；三次高成功率运行得满运行验证分；少于三次可判定运行的总分被限制在 74；59 分为未达到合格线，60 分为合格，80 分为优秀。
2. 本地简报生成和 JSON schema/响应 schema 均接受合法 `student_summary`，并拒绝范围外分数和未知字段。
3. TypeScript 测试覆盖提交成功后调用本地简报读取，学生模式仅渲染完成情况、综合评分和说明；补传中也显示本地简报。
4. 现有学生提交、普通本地简报和课堂同步相关测试继续通过。

## 风险与回滚

评分是过程证据评分，学生可以看到分数但不能把它解释为题目最终正确性。评分函数与简报渲染保持确定性且不调用 AI，因此不会新增模型费用或上游故障。若需回滚，只删除 `student_summary` 的使用并回退对应 schema/UI；旧本地简报文件无需迁移。
