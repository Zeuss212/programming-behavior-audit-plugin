# BAMS 课堂学生镜像 0.4.0 测试部署设计

## 1. 目标与阶段合同

本设计把 `myextension 0.4.0` 课堂学生镜像部署到一条与生产隔离的 BAMS 测试链路，
并完成学生行为采集、课堂同步、教师简报查看和回滚验证。仅能创建或打开 Notebook
不构成完整实现。

本阶段允许：

- 校验并重新生成本地 `0.4.0` buildkit；
- 在独立 Linux AMD64 Docker 构建机上构建、验证和导出候选镜像；
- 经单独授权后，在 BAMS 中导入候选镜像并新建测试框架、测试模板和测试工作台；
- 经单独授权后，启动隔离的候选 FinColab 前端并执行端到端验收。

本阶段禁止：

- 覆盖生产 `framework_id=1`、现有学生模板或运行中工作台；
- 删除旧镜像、持久卷、课堂证据、简报或失败工作台；
- 将 API Key、平台 JWT、对象存储凭据或课堂票据写入文件、镜像层、模板、命令参数或日志；
- 在缺少正式 HTTPS 课堂同步地址时宣称端到端完成；
- 未经单独授权调用真实付费 AI、修改数据库、推送镜像、替换模板或发布前端。

设计完成后的停止点是：形成经过用户审阅的实施规范和实施计划。设计批准本身不授权任何
服务器写操作、镜像导入、模板变更、容器启动或真实 AI 调用。

## 2. 已确认基线

- BAMS/BLUEDOT 学生工作台入口为 `https://14.103.139.131:40037`。
- FinColab 生产前端固定使用 `VITE_STUDENT_DEFAULT_FRAMEWORK_ID=1` 和
  `VITE_STUDENT_DEFAULT_TEMPLATE_ID=2`；其中 `framework_id` 决定 AI 框架/工作台镜像，
  `template_id` 是代码模板，不是容器镜像。
- 当前正在运行的自定义学生镜像为：

  ```text

  ```

- 服务器侧只读检查确认该镜像架构为 `amd64`；它是 CPU、JupyterLab 4、
  `myextension 0.2.2` 的已运行基线。
- `0.4.0` 发布目录当前 wheel 的 SHA-256 为
  `09aab78afebf51c552f353b0f3c2f68095ce1f1e3882be79c62abb6de145ab82`，目录内
  `SHA256SUMS` 校验通过。
- 现有 buildkit 压缩包内部记录的 wheel SHA-256 仍为
  `e3428347d5c444cece55096efa1bdc59b19fc94b6ba44b4c254d64c31732baaf`。
  因此当前压缩包与当前发布目录不一致，实施前必须重新生成并校验，不能直接上传。
- 当前项目 `main` 工作树包含其他未提交修改；后续实施必须隔离文件范围，不覆盖或提交

- 正式课堂同步 HTTPS `/classroom-api` 地址尚未确认。`40037` 目前只能确认是门户和
  Notebook 工作台入口，不能在缺乏路由证据时直接当作同步地址。

## 3. 方案选择

### 3.1 推荐路径：干净基础镜像

由 BAMS 运维提供平台原始 `PyTorch 2.5.1 + JupyterLab 4` 的不可变
`repository@sha256:` 加 64 位摘要的引用。在独立 Linux AMD64 Docker 构建机上，以该引用为基础
安装 `myextension 0.4.0`。这是默认路径，因为镜像依赖关系清晰、构建可重复、后续升级和
审计成本最低。

### 3.2 兼容回退：在 0.2.2 已运行镜像上覆盖安装

若平台无法提供原始基础镜像 digest，则先取得当前 `0.2.2` 镜像的不可变 digest，再将其
作为基础镜像。`Dockerfile` 使用 `--force-reinstall` 覆盖安装 `0.4.0`，并通过前后端扩展、
版本和运行能力检查确认旧包未继续生效。该路径保留旧历史层，只作为兼容回退。

### 3.3 明确排除：原地修改工作台或生产模板

不在现有工作台执行临时 `pip install`，不修改运行中容器，也不把生产 `framework_id=1`
直接改指新镜像。这些做法不可复现、会影响现有学生，并且无法建立可靠回滚证据。

## 4. 架构与阶段门槛

### 4.1 交付物门槛

重新生成 `behavior-audit-classroom-0.4.0-linux-amd64-buildkit.tar.gz` 及其校验文件。
发布目录 wheel、`SHA256SUMS`、buildkit 内 wheel 和 buildkit 内清单必须逐字节一致。
buildkit 只能包含清单声明的 Dockerfile、脚本、文档、运行配置样例和候选 wheel。

### 4.2 基础镜像门槛

基础镜像必须满足：

- 不可变 `repository@sha256:` 加 64 位摘要的引用；
- Linux AMD64；
- Python 3.10+；
- JupyterLab 4.x；
- Jupyter Server 2.x；
- 已安装 `jsonschema`；
- 保留平台所需的 `ENTRYPOINT`、`CMD`、动态 base URL 和认证行为。

推荐路径无法满足时，才进入 0.2.2 digest 的兼容回退路径。两条路径都必须重新执行完整
镜像验收，不能把当前工作台可运行等同于新镜像可运行。

### 4.3 隔离构建门槛

构建在独立 Linux AMD64 Docker 主机执行，不在承载 BAMS 工作负载的 `qhvgpu1` 上构建。
构建脚本先验证 wheel SHA-256，再固定 `--platform linux/amd64`。候选镜像使用新的版本标签，
且最终以不可变 digest 进入 BAMS；不复用或覆盖 `0.2.2` 标签。

### 4.4 导入门槛

镜像通过离线验收后才能导出 tar。导出流程再次验证镜像并拒绝非 AMD64 架构，然后生成
tar 的 SHA-256。BAMS 节点导入前复核该 SHA-256；导入只增加候选镜像，不修改现有框架、
模板或工作台。

### 4.5 测试模板门槛

通过 BAMS 支持的管理界面或 API 新建测试框架/模板记录，指向候选镜像 digest。
不直接执行数据库更新。生产 `framework_id=1` 与 `template_id=2` 保持不变。

新测试框架必须关联一份与当前 `template_id=2` 等价的测试代码模板。若 BAMS 允许同一代码
模板安全关联多个框架，则复用该代码模板；否则复制代码模板并取得新的测试模板 ID。候选前端
同时使用新测试框架 ID 和经验证的测试代码模板 ID，不能把生产关联关系改写为测试关联关系。

端到端学生路径使用隔离候选前端，并把候选前端的
`VITE_STUDENT_DEFAULT_FRAMEWORK_ID` 指向新测试框架 ID。若 BAMS 管理端允许测试账号在创建
流程中直接选择测试框架，则可以省去候选前端重建，但必须证明不会改变生产账号默认值。

### 4.6 端到端门槛

只从复制的测试模板创建新工作台。运行时挂载 `/workspace/result`，并注入：

```text
JUPYTERLAB_BEHAVIOR_AUDIT_PLATFORM_MODE=student
JUPYTERLAB_BEHAVIOR_AUDIT_SYNC_BASE_URL=${CLASSROOM_SYNC_URL}
JUPYTERLAB_BEHAVIOR_AUDIT_LOG_DIR=/workspace/result/behavior-audit
JUPYTERLAB_BEHAVIOR_AUDIT_DEADLINE_POLL_SECONDS=30
JUPYTERLAB_BEHAVIOR_AUDIT_ANALYSIS_TIMEOUT_SEC=180
```

`CLASSROOM_SYNC_URL` 是实施输入，值必须是以 `/classroom-api` 结尾、可由工作台访问的正式
HTTPS 地址。该值必须在实施门槛前由运维确认，并通过证书、路由和健康检查。它不能凭端口或页面入口
推断。缺少该地址时可以完成镜像离线验收和导入准备，但状态必须是“镜像就绪、端到端阻塞”。

## 5. 组件与数据流

1. 当前源码与发布目录生成唯一的 `0.4.0` buildkit。
2. 独立构建机从不可变基础镜像构建候选镜像，执行离线镜像验收并导出带校验和的 tar。
3. BAMS 节点导入候选镜像并得到不可变 digest。
4. BAMS 新测试框架/模板引用该 digest；生产框架、模板、前端和工作台保持不变。
5. 候选前端或 BAMS 管理端为测试账号选择新测试框架并创建测试工作台。
6. 工作台插件把行为证据写入 `/workspace/result/behavior-audit`，并使用一次性课堂票据向
   正式 HTTPS `/classroom-api` 注册和同步。
7. 课堂同步服务持久化会话、证据和简报；教师端读取学生状态、完成情况、简报和 AI 分析
   结果。
8. AI 分析失败或未授权时，基础采集、同步和非 AI 简报仍必须可用。

## 6. 错误处理与安全

- buildkit、wheel 或 SHA-256 任一不一致：停止，不上传。
- 基础镜像引用可变、架构错误或运行时版本不兼容：停止构建。
- 镜像验证失败：不导出、不导入；日志只能保留非敏感诊断信息。
- tar 校验不一致或导入失败：不创建测试框架或模板。
- 工作台启动失败：停止继续创建，保留失败工作台、Pod 事件和非敏感日志用于诊断。
- `/classroom-api` 不可达、证书无效或路由不正确：停止端到端验收，不用 HTTP、loopback
  或工作台端口绕过。
- 不执行完整容器环境导出或数据库 dump，以免泄露凭据；只读取验收所需的定向字段。
- Secret 只在运行时注入。任何输出只报告“是否存在”，不回显值。
- 真实付费 AI 调用是独立阶段门槛，需要明确的目标、预计成本、测试账号、停止条件和授权。

## 7. 回滚

实施前记录：

- 当前测试模板 ID；
- 当前 `0.2.2` 镜像不可变 digest；
- 当前生产 `framework_id=1` 与代码模板映射；
- 候选前端启用前的镜像与端口状态。

验收失败时：

1. 停止使用新测试模板创建工作台；
2. 将测试模板指回记录的旧 digest，或恢复到未创建候选模板的状态；
3. 停止候选前端并恢复其之前的隔离端口状态；
4. 保留旧镜像、新候选镜像、失败工作台、持久卷、简报和证据；
5. 不删除生产工作台、数据库记录或学生数据。

回滚成功必须通过新建一个旧模板测试工作台验证，不能只以配置写回成功作为证据。

## 8. 验收标准

### 8.1 交付物

- release wheel、release `SHA256SUMS`、buildkit 内 wheel 和 buildkit 清单一致；
- buildkit 校验和通过，只包含清单声明文件；
- 发布测试、脚本语法检查和 `git diff --check` 通过。

### 8.2 镜像

- 操作系统/架构为 `linux/amd64`；
- JupyterLab 4、Jupyter Server 2、`myextension 0.4.0` 前后端扩展均启用；
- 学生模式可采集、可提交、不可编辑教师方案；
- `/workspace/result/behavior-audit` 可写；
- 镜像内不存在已知 AI、平台或对象存储密钥；
- 基础镜像的启动命令、认证和动态 base URL 行为未被破坏。

### 8.3 测试工作台

- 无镜像拉取失败、平台不匹配或调度错误；
- 全新浏览器会话加载 `0.4.0` 前端资源而不是旧缓存；
- 完成一次最小编程行为采集并生成本地证据；
- 工作台重建后，持久卷中的行为证据仍存在；
- 超时、AI 未配置或 AI 失败时，基础采集和本地简报仍可用。

### 8.4 课堂闭环

- 测试学生使用一次性票据注册课堂会话并同步行为；
- 教师端能看到学生状态、完成情况、简报和证据；
- AI 分析失败不阻塞基础简报；真实 AI 只在单独授权后验证；
- 执行一次测试模板回滚演练，确认旧 `0.2.2` digest 可恢复且历史证据不丢失；
- 最终报告列出实际命令、镜像 digest、结果、未覆盖项和回滚证据，不包含凭据或票据。

四层验收全部通过后，状态才可标记为“测试环境完整实现”。正式替换生产框架、生产模板或
正式前端属于新的发布阶段，不在本设计授权范围内。
