# 本地演示创建实验闭环设计

## 目标

补齐本地 FinColab façade 的创建实验契约，使教师在现有三步弹窗中能使用已选课程、AI 框架、代码模板、参与学生和算力资源完成创建，刷新后能在实验列表中看到新建父实验及学生实验。

## 范围与非目标

- 只修改本地演示 façade、对应的 Python 契约测试和必要的本地演示说明。
- 保留最新前端的表格、筛选、分页和三步创建弹窗，不修改前端交互或生产 BAMS 契约。
- 新建数据只在 façade 进程内保存；容器重启后恢复固定演示数据。
- 不接入远端、不新增数据库或文件持久化、不推送或部署。

## 根因与方案选择

现有 façade 将 `/v1/spaces/course-001/datasets` 落入通用课程拒绝分支，因此第三步首先报 `demo_course_access_denied`。同时除登录外的 POST/DELETE 请求尚未实现，即使单独放行数据集查询，后续创建项目与工作台仍会失败。

采用进程内可变状态，而不是静态伪成功或持久化存储：它能按前端真实请求和返回结构完成页面闭环，同时符合本地演示可重置的原有边界。

## 组件与数据流

façade 服务器持有一个独立的演示状态，包含动态算法项目和工作台。状态属于单个 HTTP 服务器实例，测试之间不共享，并使用锁保护 ThreadingHTTPServer 下的读写。

创建流程为：

1. `GET /v1/spaces/{courseId}/datasets` 返回一个固定的 `default_dataset` 版本，使前端无需启动文件管理器上传流程。
2. `POST /v1/spaces/{courseId}/algorithm_development` 校验教师、课程和必需字段，从真实请求保留名称、描述、框架、模板、类型和数据集引用，生成本地唯一 ID 并写入状态。
3. `POST /v1/spaces/{courseId}/algorithm_development/{algorithmId}/workbench` 为已创建项目记录资源配置，返回可被现有页面识别的本地工作台。
4. `GET .../algorithm_development` 将固定演示项目与动态项目合并，供列表刷新和学生可见性判定。
5. `DELETE .../algorithm_development/{algorithmId}` 只允许教师删除动态项目及其工作台，用于前端的失败回滚。

## 权限、错误与兼容性

- 所有路由先验证本地 bearer token；课程不匹配继续返回 `demo_course_access_denied`。
- 只有教师可创建和删除；学生列表可读取自己的动态学生项目及其引用的父实验元数据，以完成首页关联，但父实验详情和其他学生项目仍被拒绝。
- 缺少或非法请求字段返回可区分的 400；不存在的动态资源返回 404；无权访问返回 403。
- 现有固定 C++ 课堂项目、材料包、身份可见性和跨课程拒绝契约保持不变。

## 验证策略

- 先新增一个 façade 端到端契约测试，覆盖数据集查询、父/学生项目创建、工作台创建、列表刷新和回滚删除，并观察它在实现前因缺少契约而失败。
- 补充学生写入拒绝、跨课程拒绝及状态隔离测试。
- 运行完整 façade 回归、相关本地演示冒烟、Ruff 和差异检查。
- 重建仅 `demo-fincolab` 容器，在 `5176` 前端实际完成一次三步创建；验证成功提示、列表新行和学生关联数据，不推送远端。

## 停止点

完成本地契约测试、页面创建闭环和本地 Git 提交后停止；不进入推送、部署或生产数据操作。
