# 本地演示短登录凭据设计

## 目标

将本地课堂演示入口的教师登录凭据改为 `1 / 1`，学生登录凭据改为 `2 / 2`，方便现场演示快速切换角色。

## 范围与非目标

- 仅修改 `deploy/classroom/local-demo` 提供的本地演示认证。
- 教师 `1 / 1` 登录后仍返回并使用内部身份 `teacher001`。
- 学生 `2 / 2` 登录后仍返回并使用内部身份 `student001`。
- 停用原教师 `teacher001 / local-demo-teacher` 与原学生 `student001 / local-demo-student` 登录组合。
- 不修改生产认证、既有 token、课堂数据主键、课程成员、任务、简报或监控记录。
- 不修改用于越权测试的 `student002` 负例账号。

## 实现方案

在本地 façade 中将“登录名”与“内部用户身份”分离：凭据表以 `1`、`2` 为登录键，用户对象继续携带 `teacher001`、`student001`。登录成功响应继续返回内部 username，确保前端启动引导、课程权限和已有数据引用保持兼容。

本地说明、烟测脚本和 façade 测试统一改用新凭据。测试还需证明旧凭据返回 `401`，避免同时保留两套入口。

## 错误处理与安全边界

- 未知登录名或密码不匹配继续返回统一的 `demo_login_rejected`，不泄露哪一项错误。
- 短凭据仅存在于一次性本地演示 fixture，不进入生产配置。
- 请求日志继续禁止输出密码和 bearer token。

## 验收标准

1. `1 / 1` 登录成功，角色为教师，内部 username 为 `teacher001`。
2. `2 / 2` 登录成功，角色为学生，内部 username 为 `student001`。
3. 两组旧凭据均返回 `401`。
4. 教师仍能读取原课程与学生名单，学生仍只能读取自己的课堂数据。
5. façade 测试、相关烟测测试和本地演示文档检查通过。

## 停止点

完成本地代码、测试、文档更新并重建本地 façade 服务；不推送、不部署。
