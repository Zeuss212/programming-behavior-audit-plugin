# 考核评价保存发布课堂方案设计

设计日期：2026-09-02

## 问题与根因

教师端当前的 `PUT /v1/classroom/experiments/{space}/{parent}/assessment-config`
只更新 `experiment_assessment_configs`。它不会创建 `plan_versions`、更新
`experiment_plan_bindings`，也不会同步 `student_assignments`。学情分析读取
`experiment_plan_bindings`，因此保存评价后仍显示“尚未发布课堂方案”。

实验创建页虽收集了说明、起止时间和学生子项目，但这些发布必需数据只在前端
弹窗内存在；关闭或刷新后无法供评价保存流程使用。

## 目标与边界

- 创建实验时将实验名称、说明、起止时间和 AI 策略保存到课堂服务数据库。
- 保存有效评价时发布（或幂等复用）对应的不可变课堂版本，并同步已验证的学生
  子项目为任务。
- 学情分析可读取该绑定并打开学生详情的既有路由。
- 不修改 BAMS API、BAMS 数据库、BAMS 镜像或部署配置；课堂服务仅读取既有的
  学生子项目清单。
- 历史实验若缺少发布上下文，首次保存评价时按创建页原默认规则使用
  `created_at` 至 `created_at + 7 天`；若创建时间不可用，则使用请求时间至
  `+7 天`。该兼容路径仅用于补齐历史记录。

## 方案

新增 `experiment_publication_contexts` 表，以 `(space_id, parent_algorithm_id)`
唯一保存教师已创建实验的发布上下文。创建实验成功且资源上传完成后，前端写入
该上下文；这一步不发布课堂版本。

课堂服务提供一个教师授权的“发布当前评价”接口。该接口读取已保存的评价与发布
上下文，生成 schema v2 课堂 profile：实验说明成为题目说明，评价维度成为可分析
的知识点和证据维度。它通过现有 `PlanService` 创建草稿、发布版本、写入
`experiment_plan_bindings`，然后用既有身份网关获取学生子项目并同步任务。

以“当前绑定版本的评价快照与上下文是否相同”为幂等键：超时重试不会创建第二个
版本；评价配置修订后才创建新版本。若 BAMS roster 读取临时失败，版本和绑定保留，
同一发布请求重试只补做任务同步。

前端保存顺序为：更新评价配置 → 调用发布当前评价 → 刷新当前绑定。保存按钮在整
个流程中禁用；成功文案明确显示已下发任务数；失败文案区分评价保存失败与“已保存
但下发待重试”。

## 验收

1. 新建实验保存的发布上下文含原始起止时间与说明。
2. 首次保存有效评价后，存在 `plan_versions`、`experiment_plan_bindings` 和每个
   已验证学生子项目的一条任务；再次以相同配置发布不增加版本。
3. 修改评价后创建一个新的不可变版本，绑定指向新版本。
4. 学情分析不再进入未配置空态，能展示学生行；拥有会话的学生可进入现有详情路由。
5. 前后端定向测试、类型检查与生产构建通过。
