# Jupyter 学生侧栏知识点与 0.4.0 升级设计

日期：2026-09-02  
范围：`myextension` 0.4.0 的学生课堂模式、构建制品与受控部署说明；不修改 BAMS 源码、数据库或课堂资源服务。

## 1. 目标、问题与停止点

教师已经在考核评价中发布知识点，但学生进入 Jupyter 后只能看到旧版“编程行为分析”面板，无法确认本次实验的学习目标。远端实例经现场命令确认加载的是 `myextension 0.2.2`，而候选基线 `2920f93` 已提供 `0.4.0`。

本次目标是让 **通过课堂任务进入的学生** 在 Jupyter 左侧“课堂监控”面板看见教师发布版本中的知识点快照，并产出可替换旧扩展的 `0.4.0` 制品与部署验收步骤。

本次停止点：隔离分支中的插件实现、测试、可安装的 0.4.0 wheel 和镜像/工作台替换操作说明均已完成并验证。实际远端替换必须在确认镜像模板、发布目标和回滚引用后单独执行。

不在本次范围：

- 修改 BAMS 源码、数据库、工作台创建流程或教师端的知识点编辑功能；
- 在学生工作区写入知识点副本；
- 把知识点当作成绩、能力判定或行为监控结论；
- 与尚未提交的“课堂资料同步”改动混合开发。

## 2. 已有可信数据链路

教师发布的评价格式为 `schema_version: 2`，其中 `profile.knowledge_points` 的每一项包含 `id`、`name`、`description` 和 `order`。该版本化 profile 已作为课堂发布快照的一部分。

学生从课堂任务启动 Jupyter 时，浏览器只提交一次性 launch ticket 给本机 Jupyter 服务。Jupyter 服务端以票据换取并私存插件访问令牌；浏览器获得的 `/myextension/platform/context` 响应只包含经过 Schema 校验的 `classroom_session.profile`，不包含令牌。现有链路为：

```text
教师发布知识点 → 课堂发布快照 → 学生 launch ticket
→ Jupyter 服务端注册/刷新会话 → /platform/context（去令牌）
→ 左侧课堂监控面板
```

因此本次只消费已存在、可信的课堂上下文；不增加浏览器直连课堂服务，也不新增 BAMS 接口。

## 3. 推荐实现

### 3.1 学生只读知识点卡片

`BehaviorAnalysisSidebar` 在 `platformContext.mode === 'student'` 时，在既有课堂会话信息前新增“本次实验知识点”区块：

- 先显示教师发布的方案标题和 `方案 v{plan_version}`；
- 用 `knowledge_points.order` 的升序显示每个知识点的名称和教师说明；
- 最多按已发布 Schema 上限渲染，所有文本使用 `textContent`，不注入 HTML；
- 卡片是纯只读内容，不出现“创建题目考核方案”、AI 配置、编辑、删除或评分控件；
- 课堂资料目录同步仍是独立功能。它成功或失败都不改变知识点卡片；知识点卡片也不创建任何工作区文件。

课堂上下文的既有 `platform-context-response-v1` Schema 已要求已发布的 schema v2 profile，且知识点至少一项。前端仍以运行时类型守卫保护渲染：若本机服务错误地提供了缺失或不合法的 profile，则显示“知识点暂时无法加载，请重试”，不访问未验证字段，也不显示作者控件。

### 3.2 刷新与状态处理

侧栏依赖新增一个受控的 `refreshPlatformContext` 回调。学生点击“刷新课堂信息”时，浏览器只调用本机的 `POST /myextension/platform/context`：服务端使用私存令牌刷新已注册会话，再返回去令牌上下文。成功后用新上下文重新渲染卡片；同一已发布任务应继续返回同一资源与知识点快照。

刷新期间按钮禁用并带 `aria-busy`。失败时：

- 保留上一次成功的知识点内容；
- 在卡片内显示“知识点暂时无法加载，请重试”；
- 不停止 Notebook 编辑、运行、采集或简报提交；
- 不把失败回退成教师作者模式。

若服务端已确认学生模式但无 `classroom_session`，面板显示“尚未接入课堂任务，请从课程页面重新进入”。直接打开普通 Jupyter、使用过期链接或无权限时不会显示任何教师配置或作者入口。

首次上下文读取失败时，扩展必须在已经识别到课堂启动票据的情况下创建中性学生侧栏，不以本地作者上下文替代。该中性侧栏只能重试上下文读取；它绝不暴露教师配置能力。

### 3.3 模块边界

| 模块 | 责任 | 不负责 |
| --- | --- | --- |
| `src/platform/contextApi.ts` | 声明和调用去令牌课堂上下文刷新接口 | 直连课堂资源或持有令牌 |
| `src/ui/behaviorAnalysisSidebar.ts` | 以只读组件展示 profile 的知识点、刷新状态与可访问提示 | 修改 profile、发布课堂任务 |
| `src/index.ts` | 在课堂 ticket 注册、上下文不可用与正常上下文三种状态中初始化正确的侧栏 | 决定教师知识点内容 |
| `myextension/routes.py` 与上下文存储 | 沿用现有服务端验证、会话刷新和 Schema 校验 | BAMS 数据迁移或浏览器令牌转发 |
| 课堂资料同步分支 | 同步“课堂资料”目录 | 本次知识点卡片实现 |

## 4. 安全、权限与兼容性

- 权限锚点是本机服务端注册的课堂会话；浏览器不接受 `assignment_id`、`plan_id` 或知识点 JSON 作为可信输入。
- 所有 `profile`、时间和版本数据在服务端既有 Schema 校验后才会返回。未知 profile 版本、缺失字段或不合法知识点都安全地渲染为不可用状态。
- 不记录、显示或传递插件访问令牌；错误消息不得包含上游 URL、请求体或学生隐私数据。
- 旧的 0.2.x 工作台在替换前保留其原有行为。升级后的 0.4.0 对没有课堂上下文的本地作者模式保持既有作者功能；学生模式始终禁止作者功能。
- 发布快照是稳定边界：教师后续编辑草稿或发布另一版本不会改变已经开始任务的知识点；学生重新从新任务进入时才会取得新版本上下文。

## 5. 测试与验收

新增或扩展前端 Jest 测试，至少覆盖：

1. 有效的 schema v2 学生上下文按 `order` 渲染方案标题、知识点名称和说明；
2. 缺失或不合法的 profile 保持中性错误状态，不崩溃、不访问未验证字段；
3. 学生模式没有作者入口和任何配置/删除按钮；
4. 刷新成功后更新卡片；刷新失败后保留上次快照、显示可重试提示且不影响提交按钮；
5. 已识别课堂 ticket 但初次上下文请求失败时，只显示中性学生状态，绝不初始化作者面板；
6. 现有课堂会话注册、采集 bootstrap 和简报提交流程仍通过。

服务端聚焦测试确认 `/platform/context` 与刷新响应继续去除 `access_token`，并保持 `profile.knowledge_points` 的已验证快照。课堂资料同步改动在其独立分支完成后，另跑联动回归，确认资源失败与知识点展示互不影响。

最终质量门禁：定向 Jest、完整 Jest、定向 Python pytest、完整 pytest、TypeScript、样式与生产 labextension 构建；wheel 的内容、哈希和隔离安装检查；JupyterLab 4.3.8 真实浏览器冒烟验证。

## 6. 0.4.0 替换与回滚

远端替换不改 BAMS 源码或数据库，但会影响随后创建或重建的 Jupyter 工作台，因此是单独的发布阶段。

发布前必须记录：当前 `0.2.2` wheel 的 SHA-256、当前工作台镜像引用/摘要、目标镜像模板、受影响的实验范围、已有运行中工作台的处置策略和可执行回滚命令。未具备这些信息时停止，不做猜测性替换。

受控顺序：

1. 从已通过测试的隔离提交构建 `myextension-0.4.0` wheel，并校验 wheel 内容和 SHA-256；
2. 在与远端相同的 JupyterLab 4.3.8 基础镜像中安装，检查 `python -c "import myextension; print(myextension.__version__)"` 与 `jupyter labextension list` 均为 `0.4.0 enabled OK`；
3. 在测试工作台用有效课堂 launch ticket 验证左侧知识点、课堂资料、编程与提交；再验证无会话时的中性状态；
4. 仅更新已明确的工作台镜像模板；对于已运行实例，按确认策略重建一个受控试点实例后再逐步替换；
5. 若版本、上下文、资源同步或基础 Jupyter 功能异常，立即停止扩大范围，以记录的 `0.2.2` 镜像/wheel 引用重建受影响实例，并保留日志供排查。

## 7. 非目标与后续项

后续可在产品确认后考虑：知识点折叠/搜索、课程目标的无障碍摘要、教师为学生配置可见性、以及资源同步分支合并后的整体验收。它们不进入本次实现，避免扩大 Jupyter 侧栏改动范围。
